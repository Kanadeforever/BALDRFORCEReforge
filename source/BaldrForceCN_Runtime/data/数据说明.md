当前版本 `v1.0.4-crashfix1` 不修改任何翻译 CSV 或 9 个差异资源。静态补丁表仍为：`battle_system_aligned_mapping_raw_871.csv`、`battle_system_patch_manifest.csv`、`encoding_normalization_manifest.csv`、`late_static_patch_manifest.csv`。

资源审计固定为：313 个 VFS 文件；11 COVERED（2 PAC + 9 loose）；302 PASS；0 REVIEW。

`BFET_Backlog风险审计.csv` 与 `脚本历史记录风险审计摘要.txt` 记录 34,184 条映射的长度/GBK 截断风险。固定数字：3909 等长、29633 中文更短、642 中文更长；若某个消费者错误使用原脚本 count 截译文，642 条中 627 条会切进 GBK 双字节；1 条中文自身引号不平衡；6 条中日引号数量变化。

v1.0.4 已在正式 opcode 0x0B value object 上修复这一类长度语义：脚本游标继续使用源 count，`dest-4 byte_count` 使用中文实际长度+NUL。因此这份风险表现在主要用于寻找**其它可能绕过 value object、仍错误复用源 count 的消费者**，而不是要求 Runtime 保留旧 byte_count。
