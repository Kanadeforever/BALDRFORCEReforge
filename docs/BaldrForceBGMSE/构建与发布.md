## 2. 依赖与工具链

全部构建都是 **cmd 批处理，不使用 PowerShell**。

需要的可执行文件：

    clang.exe        （cl 驱动模式）
    lld-link.exe
    python.exe       （只用于两个 tools 下的脚本；游戏运行时不需要 Python）

本机工具链：

    clang 22.1.7 + lld-link，位于 C:\msys64\clang64\bin

脚本的自动探测顺序（`build.bat` 与 `build_all.bat` 都是这个顺序）：

1. 先查 `PATH`；
2. 再查 `C:\msys64\clang64\bin`；
3. 再查 `C:\Program Files\LLVM\bin`；
4. 找到 clang 后，把它所在目录插到 `PATH` 最前（clang 依赖同目录的 DLL）。

找不到 clang 或 lld-link 会直接报 `[失败]` 并退出。

### 2.1 为什么用 --driver-mode=cl 而不是 clang-cl

MSYS2 的 clang64 **不提供 clang-cl.exe**（本机实测：`C:\msys64\clang64\bin\clang-cl.exe` 不存在）。所以 BGMSE（以及 VoiceSE）统一用：

    clang.exe --driver-mode=cl --target=i686-pc-windows-msvc ...

### 2.2 硬性编译开关

    /nologo /c /O2 /GS- /GR- /Zl /W4 /EHs-c- -fno-builtin-strlen

- `/Zl` 与链接期的 `/nodefaultlib` 配合，禁止悄悄引入 CRT；
- **`-fno-builtin-strlen` 是硬要求**：clang 22 会把循环识别成 strlen 调用并生成 CRT 调用，而本工程用 `/nodefaultlib`，链接期没有 strlen 可用，会直接报 `undefined symbol: _strlen`。BGMSE 与 VoiceSE 都必须带这个开关。

目标固定：

    i686-pc-windows-msvc

## 3. 一键构建

### 3.1 总脚本

    build_all.bat

依次调用四个模块的 `build.bat`，正式产物统一进入项目根 `release\`。脚本开头会做环境自检（clang / lld-link / python），每个模块独立统计成功与失败。

只编一个模块：

    build_all.bat BGMSE
    build_all.bat CN
    build_all.bat GAMEPAD
    build_all.bat VOICESE

注意：模块脚本会 `cd` 到自己的目录，所以总脚本每次调用前后都要切回项目根，并且必须用绝对路径调用模块脚本。

### 3.2 单模块构建

    source\BaldrForceBGMSE\build.bat

步骤：

1. 解析工具链（探测顺序见第 2 节）；
2. `python tools\generate_bgm_table.py` —— 重新解析两份 DAT，生成静态表与中文 CSV，失败即中止；
3. 重建干净的 `build` 临时目录，必要时创建 `..\..\release`；
4. clang 编译 `src\BaldrForceBGMSE.cpp` 为 `build\BaldrForceBGMSE.obj`；
5. lld-link 链接 `..\..\release\BaldrForceBGMSE.asi`；
6. `python tools\verify_build.py ..\..\release\BaldrForceBGMSE.asi` 验证 PE；
7. 从 `release` 删掉误生成的 `.lib` / `.exp` / `.pdb`；
8. `templete\*` 复制到 `..\..\release\`；
9. 清理中间文件与 Python 缓存。

链接命令（原文）：

    lld-link /dll /machine:x86 /nodefaultlib /timestamp:0 ^
      /entry:DllMainCRTStartup@12 /def:BaldrForceBGMSE.def ^
      /out:"..\..\release\BaldrForceBGMSE.asi" ^
      /implib:"build\BaldrForceBGMSE.lib" ^
      "build\BaldrForceBGMSE.obj"

`build.bat` 为 UTF-8 + CRLF，并执行 `chcp 65001 >nul`。

## 5. 工具说明

本模块 `tools` 下只有两个自制 Python 工具。玩家运行游戏不需要 Python；只有开发/重建时使用。

### 5.1 generate_bgm_table.py

位置：

    source\BaldrForceBGMSE\tools\generate_bgm_table.py

输入：

    source\BaldrForceBGMSE\data\BFE_BGMInfo.DAT
    source\BaldrForceBGMSE\data\BFSE_BGMInfo.DAT

校验（任何一条不符即停止生成，避免不同版本数据静默混入插件）：

- 两份文件都恰好 2049 字节；
- 主体恰好 30 × 0x44；
- 表尾恰好是 `av\0av\0av\0`；
- 每条前 0x40 按 CP932 解析资源名（遇 NUL 截断）；
- `+0x40` 按有符号 little-endian int32 读取循环点。

输出：

    source\BaldrForceBGMSE\src\BgmTable.generated.h
    source\BaldrForceBGMSE\data\BGM信息对照.csv

- 头文件用**十六进制字节数组**保存 BFSE 30 条完整 0x44 数据，不依赖 C++ 源文件字符编码；同时输出 `kBfseBgmRecordCount = 30`、`kBgmRecordSize = 0x44`、`kBgmNameSize = 0x40` 三个常量，并在每行上方写一条人类可读注释（编号、文件名、循环点）。
- CSV 以 UTF-8 BOM 写出，列：编号 / BFE资源文件名 / BFE循环点(1/100秒) / BFE循环点(秒) / BFSE资源文件名 / BFSE循环点(1/100秒) / BFSE循环点(秒)；非循环显示“非循环”。

运行时成功时会打印：

    [成功] BFE/BFSE 均验证为 30 条 × 0x44 + 9 字节表尾
    [成功] BFSE 循环曲目=28，非循环曲目=2
    [输出] ...\src\BgmTable.generated.h
    [输出] ...\data\BGM信息对照.csv

### 5.2 verify_build.py

位置：

    source\BaldrForceBGMSE\tools\verify_build.py

用法：

    python source\BaldrForceBGMSE\tools\verify_build.py release\BaldrForceBGMSE.asi

直接解析生成的 PE，逐项检查：

- `MZ` 头；
- `PE\0\0` 签名；
- Machine = i386（0x014C）；
- OptionalHeader Magic = PE32（0x010B）；
- DLL 标志（`IMAGE_FILE_DLL`）；
- `AddressOfEntryPoint` 非 0；
- 标准 Import Directory 为空（`RVA = 0` 且 `Size = 0`）；
- 导出表里存在 `InitializeASI`。

只读 ASI，不修改文件。任何一项不符就带中文原因退出非 0。

### 5.3 维护规则

如果以后 BFSE/BFE 的 BGMInfo 数据发生变化：

1. 不要手工改 `src\BgmTable.generated.h`；
2. 更新 `data` 下两份 DAT；
3. 重新跑生成器；
4. 检查中文对照 CSV；
5. 重建 ASI；
6. 同步 `docs\BaldrForceBGMSE` 下的文档。

## 6. 发布清单

`release\` 目录中属于本模块的文件只应有：

    BaldrForceBGMSE.asi
    BaldrForceBGMSE.ini

`BaldrForceBGMSE.ini` 来自 `source\BaldrForceBGMSE\templete\`，由构建脚本复制，不需要手工维护第二份。

**不应出现**在 `release` 里的文件（构建脚本会自动删除，若出现说明脚本第 7 步没跑到）：

    BaldrForceBGMSE.lib
    BaldrForceBGMSE.exp
    BaldrForceBGMSE.pdb

本模块**不发布** `BGM.pac`。BFSE 的 BGM 资源由用户自己的 BFSE 安装提供（Game 模式放 update 覆盖，Local 模式命名为 `BFSE_BGM.pac` 放 ASI 同目录）。

玩家侧最终使用只需要“ASI + INI”两个文件，加上自己的一份 BFSE BGM 包。

## 7. 构建约定

### 7.1 清临时文件

模块脚本自带清理，成功与失败路径都会执行：

    build\                （rmdir /s /q）
    __pycache__\          （递归删除）
    *.pyc                 （递归删除）

并且在构建后从 `release` 删掉误生成的 `.lib` / `.exp` / `.pdb`。

### 7.2 确定性哈希

- BGMSE（以及 VoiceSE、Gamepad）使用 `/timestamp:0`；
- CN 使用 `/Brepro`。

相同输入 + 相同工具链下，输出哈希稳定。四个模块的构建确定性均已保证。

### 7.3 templete 随包复制

每个模块的 `templete` 目录放“随 ASI 一起分发的文件”（INI 等），构建时复制到 `release`。本模块的实现是：

    xcopy /y /q /i "templete\*" "..\..\release\" >nul

`templete` 目录不存在时只打印提示，不算构建失败。

### 7.4 无 CRT 约定

四个模块都：

- `/nodefaultlib`；
- PE32 / i386；
- 无 CRT。

本模块源码自己声明最小 Win32 类型，从 PEB 解析 `kernel32.dll` 导出（含 `MODULE.Function` 转发），因此最终 `Standard Import Directory = empty`。源码另提供最小 `memcpy`/`memset`，防止 clang `/O2` 生成 CRT 调用。

需要解析的 API：VirtualProtect、FlushInstructionCache、GetModuleFileNameA、GetPrivateProfileStringA、CreateFileA、WriteFile、CloseHandle。

## 8. 已知构建问题

1. **本机 PATH 里没有 clang**：当前 shell 的 `PATH` 查不到 `clang.exe`/`lld-link.exe`，构建脚本靠第 2 节的备用路径（`C:\msys64\clang64\bin`）才能找到工具链。如果换机器，请确认这两个可执行文件在探测顺序的任一位置。
2. **`clang-cl.exe` 在本机不存在**：MSYS2 clang64 不提供它，模块脚本必须继续用 `--driver-mode=cl`。
3. **漏掉 `-fno-builtin-strlen` 会直接链接失败**：报 `undefined symbol: _strlen`。这是 clang 22 的循环合成优化 + `/nodefaultlib` 的组合结果，不是源码 bug。
4. **旧文档提到的构建脚本已不存在**：`build_clang.bat`、`build_msvc.bat`、`build_clang_linux.sh` 都不在当前仓库中（`build_clang_linux.sh` 由作者主动删除且属于 CN 模块；另外两个从未进入本仓库 git 历史，内容**待确认**）。重建统一走 `build_all.bat` / 模块 `build.bat`。
5. **`release` 目录被 `.gitignore` 排除**：克隆后需要自行构建才能得到 `release` 内容，构建产物不进版本库。
6. **本模块 `data` 下的两份 DAT 是入库的**，但同仓库 VoiceSE 模块 `data` 下的 `BFE` 与 `BFSE` 目录被 `.gitignore` 排除，克隆后无法直接构建 VoiceSE（与 BGMSE 无关，仅提醒同一个 `.gitignore` 的影响面）。
7. **Python 是构建期依赖**：`generate_bgm_table.py` 与 `verify_build.py` 失败都会让模块构建中止（`build.bat` 里 `if errorlevel 1 goto :fail`）。
