# 使用与测试说明

## 1. 需要的文件

本包不附带 BFSE 的 `BGM.pac`。

你需要从自己的 BFSE 安装中取得原始：

```text
BGM.pac
```

不要解包，不要重新压包。

## 2. 安装插件

把：

```text
BaldrForceBGMSE.asi
BaldrForceBGMSE.ini
```

放到 Ultimate ASI Loader 会加载 ASI 的目录。

测试版运行后会在 ASI 同目录生成：

```text
BaldrForceBGMSE.log
```

日志是中文 UTF-8 文本。

## 3. Game 模式：配合 Ultimate ASI Loader update

这是默认模式，也是当前最推荐先测的模式。

INI：

```ini
[BGMSE]
Source=Game
```

BFSE 的原始 `BGM.pac` 按你现在 Ultimate ASI Loader 的规则放进 `update`，让它虚拟覆盖游戏原来的 `BGM.pac`。

插件此时**完全不接管 BGM.pac 路径**，只负责：

- BFE BGM 编号 -> BFSE 同编号资源名；
- BFE 循环点 -> BFSE 同编号循环点。

因此 Ultimate ASI Loader 的虚拟文件系统仍是最终文件来源。

## 4. Local 模式：ASI 同目录独立包

INI 改成：

```ini
[BGMSE]
Source=Local
```

然后把 BFSE 原始 `BGM.pac` 重命名为：

```text
BFSE_BGM.pac
```

放在：

```text
BaldrForceBGMSE.asi
BFSE_BGM.pac
BaldrForceBGMSE.ini
```

同一目录。

插件只拦截 basename 为 `BGM.pac` 的 CreateFileA 请求，其它游戏文件全部原样传递。

## 5. 第一轮实机测试看什么

先用 Game 模式测试，因为它最贴近你当前实际使用方式。

### 启动阶段

日志应该看到：

```text
[启动] BaldrForceBGMSE v0.1-test1 初始化开始。
[成功] 已安装 BGMInfo 循环点替换与两处 BGM 资源名替换 Hook。
[模式] Game：...
[完成] 初始化成功...
```

游戏读取 `BGMInfo.dat` 后，应逐渐出现 30 条：

```text
[BGMInfo] 已替换 #1，循环点=0 (1/100秒)
...
[BGMInfo] 已替换 #29，循环点=-1 (1/100秒)
[BGMInfo] 已替换 #30，循环点=-1 (1/100秒)
```

### 播放阶段

某个 BGM 第一次真正被游戏请求时会出现：

```text
[BGM资源] 首次请求 BFSE 曲目 #N，循环点=...
```

这说明该 BGM ID 已经被换成 BFSE 同编号资源名。

## 6. 循环测试特别重要

这次 `BGMInfo +0x40` 已确认就是循环点，所以测试不能只听“有没有换歌”。

建议特别听循环点较明显的曲目，例如：

```text
#06  loop=3999 -> 39.99 秒
#15  loop=5458 -> 54.58 秒
#26  loop=4909 -> 49.09 秒
#27  loop=4140 -> 41.40 秒
```

需要确认：

- 第一次播放从曲首开始；
- 播到尾部后不是回到 0，而是回到 BFSE 指定循环点；
- 没有明显爆音、断裂、错拍或回到 BFE 原循环位置。

#29、#30 是 `-1`，应保持非循环行为。

## 7. 汉化版曲名显示

本版特意**不覆盖 BFE 内存 BGMInfo 的前 0x40 字节**。

所以如果汉化版 BGM 显示名来自 BFE 自己的数据，这些文本应该继续保持汉化状态。只有真正打开 WAV 的瞬间，传给 PAC loader 的名字才临时换成 BFSE 文件名。

请顺手检查游戏内能看到 BGM 名称的界面；如果显示完全没变化，就证明这层兼容设计成立。

## 8. 如果失败，请保留什么

只需要提供：

```text
BaldrForceBGMSE.log
```

如果是某首歌不播放，再告诉我大概是第几首/哪个场景即可。
