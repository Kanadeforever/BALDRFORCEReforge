## 2. 依赖与工具链

```text
clang 22.1.7 + lld-link   位于 C:\msys64\clang64\bin
Python 3                  生成器与静态验证（本机为 Python 3.14.6）
```

工具链探测顺序（build.bat 与 build_all.bat 的 :probe 一致）：

1. PATH；
2. C:\msys64\clang64\bin；
3. C:\Program Files\LLVM\bin。

找到 clang 后，把它所在目录插到 PATH 最前面，因为 clang.exe 依赖同目录的 DLL。

关键事实：

- 全部构建都是 cmd 批处理，**不使用 PowerShell**；
- MSYS2 的 clang64 **不提供 clang-cl.exe**（本机实测缺失），所以 BGMSE/VoiceSE 用 `clang.exe` 的 cl 驱动模式 `--driver-mode=cl`；
- CN 已改为纯 clang + lld-link 路线，不再需要 Visual Studio / MSVC；
- 四个模块都 `/nodefaultlib`、PE32/i386、无 CRT；构建确定性已保证（BGMSE/VoiceSE/Gamepad 用 `/timestamp:0`，CN 用 `/Brepro`）；
- BGMSE 与 VoiceSE 必须带 `-fno-builtin-strlen`：clang 22 会把循环合成为 `strlen` 调用，而 `/nodefaultlib` 下没有 `strlen` 可链接，会报 `undefined symbol: _strlen`。

本模块实际使用的编译与链接命令：

```bat
"%CLANG%" --driver-mode=cl --target=i686-pc-windows-msvc /nologo /c /O2 /GS- /GR- /Zl /W4 /EHs-c- -fno-builtin-strlen /Fo"build\BaldrForceVoiceSE.obj" "src\BaldrForceVoiceSE.cpp"

"%LLD%" /dll /machine:x86 /nodefaultlib /timestamp:0 /entry:DllMainCRTStartup@12 /def:BaldrForceVoiceSE.def /out:"..\..\release\BaldrForceVoiceSE.asi" /implib:"build\BaldrForceVoiceSE.lib" "build\BaldrForceVoiceSE.obj"
```

## 3. 一键构建

`build_all.bat` 依次调用四个模块自己的 build.bat：

```bat
build_all.bat              编译全部四个模块
build_all.bat BGMSE        只编译 BGMSE / CN / GAMEPAD / VOICESE 之一
build_all.bat CN
build_all.bat GAMEPAD
build_all.bat VOICESE
```

约定：

- 模块脚本先 `cd` 到自身目录，产物写上一级的上一级 `release`，所以 release 永远在项目根；
- build_all.bat 用绝对路径调用各模块脚本，每次调用前后切回包根（否则第二次调用会找不到脚本）；
- 各模块脚本负责清理自己的临时文件，build_all.bat 本身不产生中间文件；
- build_all.bat 先做 clang / lld-link / python 环境自检并打印结果，最后列出 release 内容。

只构建本模块：

```bat
source\BaldrForceVoiceSE\build.bat
```

build.bat 的步骤：

1. 解析工具链（clang.exe、lld-link.exe，按第 2 节的探测顺序）；
2. `python tools\generate_voice_table.py`：读取 `data\BFE`（必须正好 301 个脚本）与 `data\剧情语音映射_当前确定.json`，重新生成 `src\VoiceMap.generated.h`；
3. 删除并重建临时目录 `build`，确保包根 `release` 存在；
4. 清理早期测试阶段可能留在 release 里的 CSV（`剧情语音映射审计.csv`、`全游戏剧情语音覆盖清单.csv`、`待人工复核_主线45条.csv`、`待人工复核_全部.csv`）；
5. clang 编译 32 位目标（`/O2` 让运行时 FNV-1a 与二分查找足够轻量）；
6. lld-link 生成 PE32 DLL，直接以 `.asi` 为扩展名输出到 `..\..\release`；
7. `python tools\verify_build.py ..\..\release\BaldrForceVoiceSE.asi` 静态验证；
8. 删除 release 里误生成的 `.lib` / `.exp` / `.pdb`；
9. 清理 `build`、`__pycache__`、`*.pyc`。

`build.bat` 保持 UTF-8 + CRLF，并执行 `chcp 65001 >nul`。

构建输入硬性要求：`data\BFE` 下必须正好 301 个 BIN，否则生成器直接抛错（避免生成「看似成功但少脚本」的表）。

## 5. 工具说明

玩家正常运行 ASI 不需要 Python；以下工具全部用于离线构建、离线映射、人工复核与静态验证。

### 5.1 `tools\generate_voice_table.py`

- 用途：把已审核完成的「脚本 + 逻辑文本记录号 -> BFSE VoiceTag」映射转换成运行时键 `脚本执行流 FNV-1a32 + 0x000B 记录相对执行流的静态字节偏移`，并生成 C++ 静态表；
- 输入：`data\BFE`（必须正好 301 个 BIN）、`data\剧情语音映射_当前确定.json`；
- 输出：`src\VoiceMap.generated.h`（只包含 `kVoiceMap` 与 `kVoiceMapCount`；**不**恢复 `kScriptCoverage`）；控制台打印脚本数、映射脚本数、VoiceMap 条数与冲突明细；
- 安全检查：BFE 输入必须正好 301 个；执行流哈希不得碰撞；映射引用的脚本必须存在；逻辑记录号必须有效；VoiceTag 长度不得超过 7（C++ 固定字段 `char voiceTag[8]`）；运行时键 `(scriptHash, recordOffset)` 不得重复；一个 BFE 记录对应多个 VoiceTag 时整条排除；
- 不向 `release` 输出任何运行时 CSV；只读 BIN，不写回任何游戏文件。

### 5.2 `tools\verify_build.py`

- 用途：对刚编译出的 ASI 做 PE 静态验证；
- 输入：ASI 路径（命令行参数）；
- 输出：通过时打印 Machine / DLL / 空导入表 / Entry RVA / 导出名；失败时逐条列出问题并返回非 0；
- 检查项：`MZ` 与 `PE\0\0` 签名；Machine = `0x014C`（i386）；OptionalHeader = `0x010B`（PE32）；`IMAGE_FILE_DLL` 标志；`AddressOfEntryPoint` 非 0；标准 Import Directory 为空；导出同时包含 `InitializeASI` 与 `_InitializeASI@0`；
- 只读文件，不修改 ASI。

### 5.3 `tools\mapping\build_voice_map.py`

- 用途：比较 BFE 与 BFSE 的 NEXAS BIN 剧情脚本，把 BFSE 后来增加的主角语音标签映射回 BFE 的逻辑文本记录号，建立离线候选；
- 输入：`--bfe`（BFE 原始 BIN 目录，必填）、`--bfse`（BFSE BIN 目录，必填）、`--out`（结果输出目录，必填）；可选 `--voice-pattern`（主角 VoiceTag 正则，默认识别 `5xxxxx` / `6xxxxx` / `7xxxxx` / `TRxxxx`）、`--voice3-list`（Voice3 解包文件名清单，提供后核验每个 VoiceTag 是否真实存在）、`--manual-accept` / `--manual-reject`（人工确认通过 / 不通过 CSV，至少需要「脚本」「VoiceTag」两列）；
- 输出：候选 CSV/JSON 到 `--out` 指定的目录（离线研究产物，**不是**项目根 `release`）；
- 判定综合：正文相似度、局部序列、前后文、剧情锚点、人工正/负样本；模糊匹配只允许发生在这里，运行时不做模糊判断；低置信度结果进入人工复核而不自动写入最终映射；
- 只读 BIN。

### 5.4 `tools\mapping\build_review_sheet.py`

- 用途：把 `build_voice_map.py` 仍未解决的候选整理成适合一次性人工确认的表格；
- 输入：`--bfe`、`--bfse`、`--candidates`（`build_voice_map.py` 生成的完整候选 CSV）、`--out`（输出 CSV 路径），均为必填；
- 输出：人工确认 CSV，字段包含范围、脚本、VoiceTag、建议试听文件、机器等级、相似度、第二候选相似度、BFSE 记录号，以及 BFSE/BFE 目标台词与前后文、人工结论与人工备注（默认留空）；
- 关键常量：`CONTEXT_RADIUS = 20`，即展示目标前后各 20 条。它只扩大「给人看」的范围，**不提高** `build_voice_map.py` 的自动接受权限；
- 不重新做匹配，不修改任何 BIN。

### 5.5 `tools\mapping\verify_regression.py`

- 用途：用人工确认过的正/负样本作为离线映射算法的回归门禁；
- 输入：`--release`（`build_voice_map.py` 生成的离线结果目录）、`--accept`（人工确认通过 CSV）、`--reject`（人工确认不通过 CSV），均为必填；
- 输出：全部通过时返回 0；任意一条失败返回非 0，批处理随之报错；
- 检查内容：人工不通过项不能重新被机器自动接受、不能出现在最终 JSON；人工通过项必须仍然出现在最终 JSON；所有人工复核键都必须能在本轮候选里找到；
- **命名提醒**：这里的 `--release` 指离线映射研究的输出目录，与项目根的编译产物目录 `release` 同名但含义不同，勿混用。

### 5.6 数据文件的角色

`data` 下 CSV/XLSX 的作用与逐项来源见《完整接档说明.md》第 9 节；它们是离线接档证据，不参与编译，也不会被构建脚本复制到 release。

2. 生成器报告的 VoiceMap 数量符合预期（当前 5891）；

## 7. 构建约定

- **清临时文件**：构建脚本会自清 `build`、`_build`、`__pycache__`、`*.pyc`，并在构建后从 release 删掉误生成的 `.lib` / `.exp` / `.pdb`；
- **确定性哈希**：VoiceSE 链接使用 `/timestamp:0`；相同源码与工具链重复构建得到稳定哈希；
- **templete 随包复制**：项目约定每个模块的 `templete` 目录存放随 ASI 一起分发的文件（INI 等），构建时复制到 release。本模块目前没有随包文件，因此没有 `templete` 目录，`build.bat` 里也没有对应复制步骤；若将来需要随包分发文件，应放在 `source\BaldrForceVoiceSE\templete` 并补上复制步骤（当前状态：未实现）；
- **自动生成物不手工编辑**：`src\VoiceMap.generated.h` 由 `generate_voice_table.py` 生成；要继续改映射，应更新上游确认数据与 `data\剧情语音映射_当前确定.json` 后重新生成；
- **`/nodefaultlib` 是硬约束**：源码不得依赖 CRT。当前源码自带最小 `memcpy`，并用自写 `StringEquals` / `StringLength` 代替 `strcmp` / `strlen`，编译期再加 `-fno-builtin-strlen` 防止编译器自动合成 CRT 调用；
- **脚本编码**：`build.bat` 保持 UTF-8 + CRLF，并 `chcp 65001 >nul`。

## 8. 已知构建问题

1. **CN 模块工具未随重组更新**：`source\BaldrForceCN_Runtime\tools` 下的 `verify_static.py`、`verify_release_package.py`、`audit_bfet_length_semantics.py`、`audit_bfet_backlog_risks.py` 仍在用重组前的旧路径（指向旧的 source、release、docs、evidence 位置），当前跑不通；而且 evidence 目录并不存在。这不影响 CN 的编译，但 CN 的重建后验证链条目前是断的。（属 CN 模块；VoiceSE 自己的工具已经使用当前结构。）
2. **已删除的历史构建脚本**：旧文档引用过的 `build_clang.bat`、`build_msvc.bat`、`build_clang_linux.sh` 都已不存在（Linux 那份是作者主动删除）。任何仍按旧名字调用的说明都已失效。
3. **克隆后无法直接构建 VoiceSE**：`.gitignore` 排除了 `release/`、`release.zip` 以及 VoiceSE 的 `data` 下 `BFE/` 与 `BFSE/` 目录。前两项只影响产物入版本库，后两项会让新克隆缺 301 个 BFE 脚本与 280 个 BFSE 脚本，生成器会因为脚本数不等于 301 直接失败。需要从自己的游戏安装或备份补齐这两个目录。
4. **Gamepad 需要手工放置 SDL3**：需要在 `source\BaldrForceGamepad\third_party` 下放置 SDL3 的 x86 `SDL3.dll`，否则 release 里不会出现 `SDL3.dll`（该模块的依赖放置说明见 `third_party\SDL3\依赖放置说明.txt`）。
5. **本模块没有 templete，这是有意为之**：VoiceSE 没有 INI 或其它需要随 ASI 分发的文件，release 里只有 BaldrForceVoiceSE.asi 一个文件。templete 约定只对需要随包文件的模块（BGMSE / CN / Gamepad）生效。若将来 VoiceSE 需要随包文件，按同一约定新建 source\BaldrForceVoiceSE\templete 并补上复制步骤。
6. **Python 未做存在性硬校验**：`build.bat` 直接调用 `python`，未检查它是否存在或版本是否满足；`build_all.bat` 的 `:probe` 只打印缺失提示，不会中断构建，失败会在生成器那一步才暴露。
