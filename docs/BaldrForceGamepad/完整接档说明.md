## 2. 项目目标

BALDR FORCE 2003 原版只认 DirectInput 时代的旧手柄，现代控制器接上去后 D-Pad、右摇杆、LT/RT
都不可用，菜单只能靠左摇杆。本模块用 SDL3 读现代手柄，把输入重新路由到游戏**原本就有的**
逻辑输入、鼠标和键盘查询路径上，让现代手柄在不改动游戏其它逻辑的前提下可用。

约束（这些约束决定了后面所有设计）：

- 只支持一份固定的 2003 原版 EXE 基线，不做“猜地址兼容”；
- 插件不接管光标显示、不重新设计菜单焦点与重复速率、不写剧情对象内部状态；
- 插件本体不依赖 C/C++ 运行库，不静态导入 SDL3。

## 4. 逆向结论

### 4.1 原版手柄层为什么不够用

游戏通过 `DINPUT.dll` 的 `DirectInputCreateEx` 读旧手柄，最终只保留三样东西：X、Y 与一个
32-bit 按钮位图。现代控制器常见的 POV 十字键、右摇杆、独立 LT/RT 轴从未以现代语义进入游戏输入层。
所以把 XInput/SDL 手柄直接交给原版 DInput，结果是：D-Pad 不工作或语义异常、右摇杆不可用、
LT/RT 不可用、菜单只能靠左摇杆。

### 4.2 借用的 Win32 API（游戏自己的 IAT）

插件不含 `windows.h`，也不链接 CRT，而是直接复用游戏已有导入表中的函数指针，
拿不到的几个再用游戏自己的 `GetModuleHandleA` + `GetProcAddress` 动态解析：

| 用途 | 位置 |
|---|---|
| LoadLibraryA | `0x004BE10C` |
| GetProcAddress | `0x004BE108` |
| GetModuleHandleA | `0x004BE1AC` |
| VirtualAlloc / VirtualFree | `0x004BE044` / `0x004BE048` |
| CreateThread | `0x004BE084` |
| GetModuleFileNameA | `0x004BE174` |
| CreateFileA / WriteFile / CloseHandle / SetFilePointer | `0x004BE05C` / `0x004BE070` / `0x004BE064` / `0x004BE078` |
| GetCursorPos / SetCursorPos | `0x004BE204` / `0x004BE208` |

动态解析（不在静态导入表中）：`VirtualProtect`、`FlushInstructionCache`、`GetCurrentProcess`、
`GetTickCount`、`GetPrivateProfileStringA`。这也解释了为什么成品的 Import Directory 是空的。

### 4.3 统一逻辑输入对象 `0x007CF218`

游戏把键盘/旧手柄统一成 16-bit 逻辑输入，对象基址 `0x007CF218`。已确认的结构：

| 偏移 | 内容 |
|---|---|
| `+0x00` | 16-bit 逻辑输入；低四位是方向：`0x0001` 上、`0x0002` 下、`0x0004` 左、`0x0008` 右 |
| `+0x04` | 当前方向字节（`0x007CF21C`，跑步判定直接读它） |
| `+0xB8` | 20 个 WORD 的手柄映射槽 |
| `+0xC8` ~ `+0xD8` | 前 9 个动作映射 WORD，依次对应逻辑 `0x0010, 0x0020, … , 0x1000` |
| `+0xE4` | 输入历史环形缓冲索引（使用时 `& 31`） |
| `+0xE8` | 32 个 WORD 的输入历史数组 |

映射槽的语义是**位掩码**：某个 WORD 里的哪一位被置上，就代表“第几个物理按钮可以触发本动作”。
目标 EXE 默认 `+0xD2 = 0x0200`，即第 10 个物理按钮触发逻辑 `0x0200`——这正是 XIDI 的 START 第 10 键，
所以早期让 START 扮演第 10 键能自然恢复部分菜单的 Start 语义。

逻辑 `0x1000` 是键盘 Esc 位，静态证据来自原版默认键盘映射表：`DIK_ESCAPE = 0x01 -> 0x1000`。

游戏还维护 32 帧输入历史，用于边沿、连发与原版双击跑步判定。

### 4.4 键盘：原始状态表与 `0x40C700`

| 地址 | 含义 |
|---|---|
| `0x00504A7C` | DirectInput 原始键盘 256 字节状态表，按下的键其最高位 `0x80` 为 1 |
| `0x0040C700` | 游戏自己的“查一个 DIK 扫描码是否按下”函数，`__cdecl`，参数是扫描码，返回 0/1 |

练习模式的退出路径**绕过统一逻辑输入**，在 `0x42E990` 直接：

```text
push DIK_ESCAPE (0x01)
call 0x40C700
```

这是 START=Esc 必须额外 Hook `0x40C700` 的原因，也是 test4 失败的根因（见 6.1）。

本模块用到的扫描码：`DIK_ESCAPE 0x01`、`NUMPAD7 0x47`、`NUMPAD8 0x48`、`NUMPAD9 0x49`、
`NUMPAD4 0x4B`、`NUMPAD6 0x4D`、`NUMPAD1 0x4F`、`NUMPAD2 0x50`、`NUMPAD3 0x51`、
`DIK_UP 0xC8`、`DIK_LEFT 0xCB`、`DIK_RIGHT 0xCD`、`DIK_DOWN 0xD0`。

### 4.5 鼠标：采集层、公开层与按钮位

游戏主循环 `0x457160` 先调用 `0x40C750` 采集实体鼠标，再调用 `0x40C710` 把内部状态复制到供 UI 读的地址。

| 地址 | 角色 |
|---|---|
| `0x00504A60` / `0x00504A64` | 客户区鼠标 X / Y（采集层） |
| `0x00504A74` | 采集层鼠标按钮状态（当前态 + 本帧刚按下态） |
| `0x007CF340` / `0x007CF344` | UI 可见鼠标 X / Y（公开层） |
| `0x007CF348` | UI 可见按钮位（公开层） |
| `0x0040C750` | 原生鼠标采集函数（`__cdecl`，无参数） |
| `0x0040C710` | 原生鼠标 getter：参数 1 出 X，参数 2 出 Y，参数 3 出按钮位 |

鼠标按钮位（`0x40C750` 的机器码已确认）：

```text
bit 0 = 左键按住
bit 1 = 右键按住
bit 2 = 左键本帧刚按下
bit 3 = 右键本帧刚按下
```

右摇杆鼠标复用 Windows 光标坐标（`GetCursorPos`/`SetCursorPos`），因为原版 `0x40C750` 本来就是
通过 `GetCursorPos` 取坐标，这样客户区/窗口换算完全保持原样。

### 4.6 跑步判定：`0x41866A` 与原版双击窗

`0x004185F0 ~ 0x004186CB` 附近是原版跑步判定：读取当前方向与输入历史，识别“松开后再次按同方向”
的双击，然后进入原版跑步 action 2。

关键入口 `0x0041866A` 的原始 5 字节是：

```text
A0 1C F2 7C 00      mov al, byte ptr [0x7CF21C]
```

它后面紧接原版双击检测。插件在这里分流：

- `FORCE_RUN`：左摇杆/方向键正在给方向，直接跳到 `0x004186B8`（原版调用 action 2 的路径）；
- `ORIGINAL`：D-Pad、数字小键盘以及未被接管的来源，先补执行被覆盖的 `mov al,[0x7CF21C]`，
  再回到 `0x0041866F` 继续游戏原本的双击判定。

插件**不伪造两次按键**，跑步完全复用游戏自己的动作路径；也刻意没有 `FORCE_WALK` 模式（见 6.5）。

### 4.7 五个正式 Hook

| 地址 | 作用 | 覆盖长度 | 原始机器码 |
|---|---|---|---|
| `0x0040C700` | 原生键盘扫描码查询：游戏问 `DIK_ESCAPE` 且 START 按住时直接返回 1 | 6 | `8B 4C 24 04 33 C0` |
| `0x0040C710` | 原生鼠标 getter：把 LT/RT 的按钮位补到最终输出 | 6 | `8B 44 24 04 85 C0` |
| `0x0040C750` | 原生鼠标采集：右摇杆移动 + LT/RT 合并进源状态 | 7 | `83 EC 08 8D 44 24 00` |
| `0x00411920` | 统一输入处理：SDL3 普通按钮、方向来源、键盘固定方案、START 的 Esc 位 | 5 | `51 53 55 56 57` |
| `0x0041866A` | 跑步判定 Gate：左摇杆/方向键直接跑，D-Pad/8246 走原版双击判定 | 5 | `A0 1C F2 7C 00` |

前四处用 trampoline Hook（`VirtualAlloc` 分配可执行内存保存被覆盖字节 + 跳回原函数剩余部分），
第五处用直接 5 字节 `E9` 跳转（原指令在 Hook 内部自行补执行）。
写入前后都会切换/恢复页保护，并调用 `FlushInstructionCache`。

`0x483CA0` 从 test7 起不再 Hook，也不再属于运行时验证签名。

### 4.8 物理按钮槽位 1~12

为兼容原版与已有 XIDI 的物理按钮编号，SDL3 普通按钮按固定槽位坐标构造：

```text
bit 0  = A        bit 6  = 空（LT 独占鼠标右键）
bit 1  = B        bit 7  = 空（RT 独占鼠标左键）
bit 2  = X        bit 8  = BACK
bit 3  = Y        bit 9  = 空（START 独占 Esc）
bit 4  = LB       bit 10 = L3
bit 5  = RB       bit 11 = R3
```

不能因为 7/8/10 为空就把后面的位整体前移，否则 BACK/L3/R3 会错位。
普通按钮通过游戏自己的映射槽（`+0xC8` 起 9 个 WORD）转换：`logical |= 0x0010 << i`。

### 4.9 test1~test6 剧情 Right 菜单相关地址（历史，不在运行时）

test1~test6 曾逆向并使用过 `0x00483CA0`（剧情对象 Hook）、`0x00486C60`、`0x005B3140`、
`0x0072DC78`、“メニューショートカット”、Message.ani 扫描、右侧小图标栏 state/focus/item、
侧栏 action 8 自动化等。这些在 test7 全部从运行时代码删除；test7 当时还静态检查过正式 ASI 中
已不再出现 `0x483CA0`、`0x5B3140`、`0x72DC78`。

结论与失败过程保留在第 6.4 节，供将来另开研究线时复查；**不要把它们直接塞回正式插件**。

## 5. 已成功方案

### 5.1 START = 键盘 Esc

三层同时生效，缺一不可：

1. 统一输入层：START 按住时 `logicalMask |= INPUT_ESCAPE (0x1000)`；
2. `0x40C700` Hook：游戏直接问 `DIK_ESCAPE` 时返回 1，覆盖练习模式这类绕过统一输入的代码；
3. 在查询 Esc 时顺手 `SDL_UpdateGamepads` 一次，避免练习模式读到上一帧的 START 状态。

用“当前按住”而不是只发一帧脉冲，边沿/连发由原版 `0x411920` 自己算。
用户已在 test5 实机确认练习模式可退出。**除非出现新的明确回归，不要重写这条路径。**

### 5.2 LT/RT 鼠标键（双层注入）

- RT = 鼠标左键，LT = 鼠标右键，两者都不进入游戏普通手柄按钮映射；
- 根据上一帧状态同时构造 held 与 pressed edge 位；
- `0x40C750` 采集完真实鼠标后，把同一份按钮位 OR 进源状态 `0x00504A74`；
- `0x40C710` getter 返回给 UI 时，再把同一份按钮位 OR 进最终输出。

用户已在 test5 实机确认点击正常。

### 5.3 右摇杆鼠标

摇杆比例 × 900 像素/秒 × Sensitivity × 本帧毫秒数，全程 32-bit 整数（避免无 CRT 时引入 64-bit 除法帮助函数）。
死区内的值先归零，越出死区后重新拉伸到 0..32767 再做缩放，防止刚过死区时跳变；单帧时间上限 50 ms。

### 5.4 战斗移动的方向分流

```text
D-Pad：        单按/按住 -> 原版步行；双击同方向并保持第二下 -> 原版跑步
数字小键盘 8246：同上；7913 等四个对角键保留原版斜向
左摇杆：       有明确方向 -> 直接走原版跑步 action
键盘方向键：   直接跑步
```

优先级：直接跑来源（左摇杆/方向键）> 原版来源（D-Pad/小键盘）；两者都没有时保持 `ORIGINAL`。
只要 SDL 手柄已打开、或键盘正在用插件固定的方向键方案，就清掉原版 DInput 产生的方向位，
避免同一只手柄被老 DInput 与 SDL3 各读一次；该规则同时让游戏设置无法反向覆盖这套固定分工。

### 5.5 战斗外方向输入

D-Pad 与左摇杆都进入同一套原版方向逻辑，标题、普通菜单、设置、剧情界面都能用十字键导航。
插件不重做菜单焦点与重复速率，也不消费 Right。

### 5.6 SDL3 运行时动态加载

插件只声明自己会用到的 SDL3 C ABI 函数指针，运行时 `LoadLibraryA("SDL3.dll")` +
`GetProcAddress` 逐个获取：`SDL_InitSubSystem`、`SDL_SetMainReady`、`SDL_UpdateGamepads`、
`SDL_GetGamepads`、`SDL_OpenGamepad`、`SDL_CloseGamepad`、`SDL_GamepadConnected`、
`SDL_GetGamepadAxis`、`SDL_GetGamepadButton`、`SDL_free`、`SDL_GetError`。

缺少必要导出时只停用 SDL3 手柄部分，键盘相关 Hook 照常工作，不会让游戏在 DLL Loader 阶段因缺依赖而报错。

## 6. 已失败与已证伪方案

这一节是本文最有价值的部分：以下每一条都已经用实机或反汇编证伪，不要重复尝试。

### 6.1 START 的三次错误做法

| 版本 | 做法 | 实机结果 |
|---|---|---|
| test2/test3 | START 继续扮演旧手柄第 10 个物理按钮（走映射槽 `+0xD2`） | 部分菜单可用，但练习模式无法退出 |
| test4 | 只在统一 16-bit 输入里 OR `0x1000` | 练习模式仍无法退出 |
| test5 | 追加 `0x40C700` 的 `DIK_ESCAPE` 响应 | 通过 |

test4 的失败直接证明：**统一逻辑输入层不等于全部输入路径**，老代码会直接查键盘。

### 6.2 LT/RT 的单层注入

test3 把 LT/RT 写在较晚的公开层 `0x7CF348`，实机点击无效——部分原版消费路径在那之前就已读取。
test4 改为合并到采集层 `0x504A74`，实机仍无点击效果。test5 改为采集层 + getter 输出层双层注入才成功。
结论：只写一层不可靠，两层写的是同一份按钮位，不存在语义冲突。

### 6.3 光标自动隐藏（已永久删除）

用户多轮实机确认 test3/test4 的隐藏规则无法覆盖游戏全部光标形态，包括 VOICE 圆形光标。
继续逆向的成本与维护风险不值得。test5 起已删除：`AutoHideSeconds`、光标可见状态机、
普通光标/VOICE 光标识别、`Cursor.spr` 槽位隐藏、光标绘制 Hook。

当前插件完全不负责光标显示/隐藏，由原版自己决定。将来若重新研究，必须作为独立实验线。

### 6.4 剧情 Right 菜单（test1~test6 全部失败，test7 永久删除运行时功能）

| 版本 | 做法 | 实机结果 |
|---|---|---|
| test1 | 把 Right 伪装成逻辑 `0x0020` / B 类菜单快捷 | 只是重复 B 原本就能做的另一种菜单操作，不是用户目标 |
| test2 | 直接维护右侧小快捷栏的 `state/focus/item` | 战斗中 Right 仍误响应；出现“从快捷菜单进入剧情地图、返回后进程不死但剧情无法继续”的恶性软锁风险。直接写内部状态的做法**永久废弃** |
| test3 / test4 | 用 Message.ani、非战斗判定、安全门槛、绘制证据限制触发范围 | 正常有对话框时仍可能打不开，目标菜单识别也不稳定 |
| test5 | 确认真正目标是“鼠标悬停右侧小图标栏，再点最下面 action id 8 按钮出现的完整菜单”；插件直接执行 action 8 | 日志显示已执行，但画面必须再动一下右摇杆才出现——跳过了原版 hover/hit-test/click/UI 提交流程 |
| test6 | 跨帧复刻：右边缘 hover -> action 8 hit-test -> 左键 pressed | 用户最终确认依然无效 |
| test7 | 按用户要求完全删除 | 删除 `0x483CA0` Hook、Message.ani 扫描、剧情菜单全部全局状态、Right 按下沿记录、action 8 / 侧栏 hover / 临时鼠标自动化；Right 不再被插件消费 |

如果将来重新研究，必须作为独立支线重新证明，不得把 test1~test6 的代码塞回正式插件。

### 6.5 D-Pad“永远只能步行”（已修正的错误设计）

早期设计把 D-Pad/8246 定义为永远只能步行。用户指出正确目标应是保留 PC 原版语义，
因此 test3 起 D-Pad/8246 不再锁步行，而是完整保留双击跑；源码中特意不提供 `FORCE_WALK` 模式。

## 7. 运行架构

### 7.1 加载与初始化时序

1. ASI Loader 走 `DllMain(DLL_PROCESS_ATTACH)` 或导出 `InitializeASI`，两者都会调用
   `StartInitializationOnce`（用 `g_initStarted` 保证只初始化一次）；
2. 先做一次基线核对，然后 `CreateThread` 起初始化线程——这样做是为了避免在 Windows Loader Lock 里
   调 `LoadLibrary(SDL3.dll)`；
3. 初始化线程：核对基线 -> 清空日志并写“目标 EXE 特征验证通过” -> 解析系统 API -> 读 INI ->
   加载 SDL3 函数 -> 安装五个 Hook；
4. `SDL_InitSubSystem(SDL_INIT_GAMEPAD)` **不在**初始化线程做，而是在第一次进入主输入对象的
   `0x411920` Hook 时做，满足 SDL 对主线程的要求；若 SDL3 提供 `SDL_SetMainReady` 会先调用它；
5. 手柄搜索约每秒一次，不每帧枚举；手柄断开时关闭并重新搜索。

### 7.2 三个输入时刻

每个游戏帧里插件会在三处刷新 SDL3 手柄状态，保证时序与游戏自身的读取顺序一致：

| 时刻 | 刷新内容 |
|---|---|
| `0x40C750` 鼠标采集（最早） | `SDL_UpdateGamepads`、手柄搜索、右摇杆移动光标、LT/RT 按钮注入 `0x504A74` |
| `0x411920` 统一输入 | SDL 主线程初始化、`SDL_UpdateGamepads`、按钮/方向/Esc 注入 |
| `0x40C700` 查询 Esc | 刷新一次 `SDL_UpdateGamepads`，避免读到上一帧 |

### 7.3 每一帧的数据流

```text
SDL3 手柄
  ├─ 普通按钮位 (1~12 坐标) ──> 游戏手柄映射槽 (+0xC8..+0xD8) ──> 合并进 logicalMask
  ├─ D-Pad ──> 方向位 ──> 与数字小键盘合并 ──> g_moveMode = ORIGINAL
  ├─ 左摇杆 ──> 方向位 ──> 与方向键合并 ──> g_moveMode = FORCE_RUN
  ├─ START ──> logicalMask |= 0x1000；并响应 0x40C700 的 DIK_ESCAPE 查询
  ├─ 右摇杆 ──> SetCursorPos（客户区换算交给原版 0x40C750）
  └─ LT/RT ──> 鼠标按钮位 ──> 0x504A74（采集层）+ 0x40C710 输出（公开层）

最终方向位写回 logicalMask 的低四位，并同步写一份到输入历史当前槽（state+0xE4 索引 &31，
historyBase = state+0xE8），再调用原版 0x411920 完成边沿/连发处理；
0x41866A 的跑步 Gate 依据 g_moveMode 决定“直接 action 2”还是“走原版双击判定”。
```

### 7.4 日志

日志文件名由 ASI 自身路径推导（同目录、同主名、扩展名换 `.log`），例如
`BaldrForceGamepad.log`。初始化时用 `CREATE_ALWAYS` 清空，之后逐行追加，所以每次运行只看到本轮结果。

正常启动至少应出现：

```text
[BaldrForceGamepad v0.1-test7] 目标 EXE 特征验证通过。
[配置] 已读取 BaldrForceGamepad.ini。
[SDL3] 运行库已载入；手柄子系统将在游戏主线程初始化。
[SDL3] 手柄子系统已在游戏线程初始化。
[SDL3] 已打开第一只可用手柄。
[成功] 原生键盘查询、鼠标 getter/采集、统一输入、步行/跑步 Hook 已安装。
```

test7 起日志中**不应再出现**：剧情菜单、Right 请求、action 8、Message.ani、右侧快捷栏。
若出现 `[SDL3] 未找到 SDL3.dll` 或 `[SDL3] 缺少必要导出`，说明运行库没放对或不是官方 x86 版本
（此时键盘相关 Hook 仍会安装成功）。

## 8. 使用与配置

### 8.1 玩家需要放置的文件

```text
游戏目录\BaldrForceGamepad.asi
游戏目录\BaldrForceGamepad.ini
游戏目录\SDL3.dll              （x86，32 位）
```

INI 必须与 ASI 同目录同名（插件按自身模块路径推导配置与日志路径）。

### 8.2 INI 参数

当前只开放一个用户参数：

```ini
[Mouse]
Sensitivity=1.00
```

右摇杆控制鼠标的速度倍率。`0.50` = 一半，`1.00` = 默认，`2.00` = 两倍；
内部把有效范围限制在 `0.10 ~ 5.00`，防止异常值导致鼠标不可控。
解析最多取三位小数，按千分比保存为整数（1.25 -> 1250）。

固定死区/阈值目前**不**暴露到 INI：左摇杆死区 8000、右摇杆死区 8000、扳机阈值 8000。

### 8.3 固定输入规则

| 输入 | 战斗 | 战斗外 |
|---|---|---|
| D-Pad | 原版单按走、双击并保持跑 | 原版方向导航 |
| 左摇杆 | 直接跑 | 原版方向导航 |
| 数字小键盘 8246 | 原版单按走、双击跑 | 同左 |
| 数字小键盘 7913 | 原版斜向 | 同左 |
| 键盘方向键 | 直接跑 | 同左 |
| START | 等价键盘 Esc（含练习模式退出） | 同左 |
| LT / RT | 鼠标右键 / 鼠标左键 | 同左 |
| 右摇杆 | 鼠标指针 | 同左 |
| A/B/X/Y/LB/RB/BACK/L3/R3 | 走游戏原版手柄映射 | 同左 |

不提供开关：这些规则本来就是用户确认过的固定方案，游戏设置里的方向键/小键盘切换不会反过来改变它。

### 8.4 SDL3 依赖

```text
SDL 3.4.16
Windows x86 / 32-bit
发行包：SDL3-3.4.16-win32-x86.zip
记录的 ZIP SHA-256：beb4e86e4a101f66556162c3efff9fd1ad88f1761b63be35867a3336a72f8c41
```

游戏和 ASI 都是 32 位，必须用 x86 的 `SDL3.dll`，不能用 x64 或 ARM64。
开发者把核验过的 DLL 放在 `source\BaldrForceGamepad\third_party\SDL3\SDL3.dll` 后运行构建脚本，
脚本会自动复制到 `release`（当前仓库里没有这个 DLL，需要手工放，见《构建与发布.md》第 8 节）。

缺少 `SDL3.dll` 时，现代手柄相关功能全部不可用（D-Pad、左右摇杆、SDL3 按钮、START=Esc、LT/RT 鼠标键），
但不影响键盘相关路径，也不会让游戏启动失败。

### 8.5 与 CN / VoiceSE 共存

常见组合：`BaldrForceCN v1.0.4-crashfix1` + `BaldrForceVoiceSE v0.1.1-test1` + `BaldrForceGamepad v0.1-test7`。

此前的静态地址交叉审计没有发现 CN / VoiceSE 与 Gamepad 当时的 Hook 入口覆盖同一段机器码；
test7 又删掉了 `0x483CA0` 剧情对象 Hook，理论交叉面进一步变小。
注意：**静态不重叠不等于运行时必然无冲突**，最终以三插件组合实机测试为准。

## 9. 测试要点与通过标准

test7 的测试重点是“确认删除 Right 菜单后其余功能没有回归”。

1. **启动日志**：应出现 7.4 的几条；不应出现剧情菜单 / Right / action 8 / Message.ani / 右侧快捷栏。
2. **Right 删除回归（最高优先级）**：在战斗、正常剧情对话、剧情地图、普通菜单、标题、场景切换前后
   反复按方向右。预期：不打开任何剧情快捷菜单、不延迟弹出、不移动内部鼠标到右边缘、
   不改变剧情对象 focus/state，Right 只按原版方向逻辑工作。
3. **START=Esc 回归**：进练习模式按 START，应和键盘 Esc 一样退出；在可用 Esc 返回的普通菜单再确认一次。
4. **LT/RT 回归**：在真正支持鼠标点击的界面确认按下能触发、松开不粘、连点正常、
   且 LT/RT 不额外触发游戏普通手柄动作。
5. **右摇杆鼠标**：上下左右连续移动；小幅移动是否平滑；Sensitivity 是否生效（不需要测自动隐藏）。
6. **战斗 D-Pad 原版语义**：四方向都要测——单次按住=步行，松开后快速双击同方向并保持第二下=跑步。
7. **左摇杆直接跑**：从静止直接推杆应无需双击即进入原版跑步；再测轻微方向变化、连续转向、
   攻击前后移动、多次停下再起步。
8. **键盘固定方案**：无论游戏设置选哪套方向方案，都要验证 8246 走/双击跑、7913 斜向、方向键直接跑。
9. **战斗外 D-Pad 菜单**：标题、设置、普通列表、剧情 UI 中 D-Pad 能与左摇杆同样导航；
   不出现一次输入跳两格；不出现 Right 被插件吃掉。
10. **三插件组合回归**：读档进剧情 -> 剧情推进 -> 剧情地图进入/返回 -> 战斗 -> 练习模式 START 退出 ->
    鼠标相关 UI -> 再回剧情。重点观察是否还有 test2 那类“进程未卡死但剧情无法继续”的软锁。

通过标准（全部满足即可视为稳定基线并准备 v0.1 RC）：

- Right 剧情菜单功能完全不存在；
- START=Esc 不回归、LT/RT 不回归；
- 右摇杆鼠标正常；
- D-Pad 原版走/双击跑正常、左摇杆直接跑正常；
- 战斗外 D-Pad 菜单正常；
- CN + VoiceSE 共存无软锁。
