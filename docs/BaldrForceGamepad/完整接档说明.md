# BaldrForceGamepad v0.1-test7 完整接档说明

> 本文档是截至 v0.1-test7 的累计接档资料。任何后续开发者只拿到本包，也应能知道目标 EXE、输入架构、关键地址、已经实机通过的方案、失败方案、踩坑、测试结论、共存情况、当前阻塞项与下一步。

## 1. 当前版本结论

当前版本：`v0.1-test7`。

本版最大的变化不是新增功能，而是**主动删除一个连续多版无法稳定实现的功能**：从 test7 起，插件完全不再接管“方向右打开剧情右侧快捷菜单/完整菜单”。Right 在任何场景都恢复为游戏原版方向右语义，不做延迟触发、不做剧情对象判断、不伪造鼠标、不写快捷栏 state/focus，也不 Hook `0x483CA0`。

当前保留并继续维护的功能只有以下几类：

1. SDL3 现代手柄输入前端；
2. 战斗移动：D-Pad 保留 PC 原版“按住走、双击并保持跑”，左摇杆直接跑；
3. 键盘固定移动：数字小键盘 8246/7913 保留原版走/双击跑，方向键直接跑；
4. 战斗外 D-Pad 与左摇杆都能进入游戏原版方向导航；
5. START 固定等价键盘 Esc；
6. 右摇杆控制游戏鼠标；
7. LT=鼠标右键，RT=鼠标左键；
8. 不提供任何鼠标光标自动隐藏功能；
9. 不提供任何 Right 剧情快捷菜单功能。

其中 START=Esc 与 LT/RT 鼠标左右键已经在 test5 实机确认成功，应视为当前可靠基线，不要无理由重写。

## 2. 唯一目标 EXE

文件：`BaldrForce.2003.exe`

- 大小：`987,136 bytes`
- 架构：PE32 / x86
- ImageBase：`0x00400000`
- SHA-256：`5b65ecb1512b0cbf72cacdb5e981aa04f9c569698c6cab2f8877abf2d2cd42c5`

插件安装前会核对五个固定 Hook 点的机器码。任何一处不一致，都拒绝继续写入，避免误伤其他版本。

## 3. 原版输入架构已经确认的事实

### 3.1 原版 DirectInput 手柄层

游戏原版使用 `DINPUT.dll -> DirectInputCreateEx`。旧手柄最终只保留非常有限的信息：X、Y 与 32-bit 按钮位图。现代控制器常见的 POV 十字键、右摇杆、独立 LT/RT 轴并没有以现代语义进入游戏最终输入层。

这就是为什么现代 XInput/SDL 手柄直接交给原版 DInput 时会出现：

- D-Pad 不工作或语义异常；
- 右摇杆不可用；
- LT/RT 不可用；
- 菜单操作依赖左摇杆，不够方便。

### 3.2 游戏内部统一逻辑输入

游戏会把键盘/旧手柄转换成 16-bit 逻辑输入。低四位方向已确认：

```text
0x0001 = 上
0x0002 = 下
0x0004 = 左
0x0008 = 右
```

游戏还维护 32 帧输入历史，用于边沿、连发与原版双击跑步判定。

### 3.3 原版跑步判定

`0x4185F0 ~ 0x4186CB` 附近会读取当前方向和前数帧方向历史，识别“松开后再次按同方向”的双击，然后进入原版跑步 action 2。

当前设计不是伪造两次按键，而是：

- D-Pad / 数字小键盘：继续让原版历史判定工作，所以保留单按走、双击跑；
- 左摇杆 / 方向键：在跑步 Gate 处直接进入原版 action 2 路径。

## 4. v0.1-test7 五个正式 Hook

| 地址 | 作用 | 当前结论 |
|---|---|---|
| `0x0040C700` | 原版键盘扫描码查询 | START 在游戏查询 `DIK_ESCAPE(0x01)` 时直接返回按下 |
| `0x0040C710` | 原版鼠标 getter | 把 LT/RT 产生的鼠标按钮位补到 UI 最终输出 |
| `0x0040C750` | 原版鼠标采集 | 右摇杆鼠标、LT/RT 源鼠标按钮在这里合并 |
| `0x00411920` | 统一输入处理 | SDL3 普通按钮、方向来源、键盘固定方案、START 的统一 Esc 位 |
| `0x0041866A` | 原版跑步判定 Gate | 左摇杆/方向键直接跑；D-Pad/8246 走原版双击判定 |

### 4.1 机器码签名

当前源码核对：

0x40C750: 83 EC 08 8D 44 24 00

`0x483CA0` 从 test7 起**不再 Hook，也不再属于运行时验证签名**。

## 5. SDL3 设计

插件运行时动态加载 `SDL3.dll`，不把 SDL3 写进静态 Import Directory。

推荐并记录的运行库：SDL 3.4.16 Windows x86。

SDL3 负责：

- D-Pad；
- 左摇杆；
- 右摇杆；
- A/B/X/Y；
- LB/RB；
- BACK；
- START；
- L3/R3；
- LT/RT。

插件负责把这些现代输入重新路由到游戏原生输入语义。

## 6. 手柄按钮槽位规则

为兼容原版/已有 XIDI 的物理按钮编号，SDL3 普通按钮仍按下列槽位坐标构造：

```text
bit 0  = A
bit 1  = B
bit 2  = X
bit 3  = Y
bit 4  = LB
bit 5  = RB
bit 6  = 空（LT 独占鼠标右键）
bit 7  = 空（RT 独占鼠标左键）
bit 8  = BACK
bit 9  = 空（START 独占 Esc，不再作为旧手柄第 10 键）
bit 10 = L3
bit 11 = R3
```

不能因为 7/8/10 为空就把后面的位整体前移，否则 BACK/L3/R3 会错位。

## 7. START=Esc：已实机通过

### 7.1 失败方案

test2/test3 曾让 START 继续扮演旧手柄第 10 个物理按钮。实机发现练习模式无法退出。

test4 曾只在统一 16-bit 输入中 OR `0x1000`。仍然无法退出练习模式。

### 7.2 成功方案

反汇编发现练习模式会直接：

```text
push DIK_ESCAPE (0x01)
call 0x40C700
```

因此 test5 起：

1. 统一输入层仍给 START 补 `INPUT_ESCAPE = 0x1000`；
2. `0x40C700` Hook 在游戏直接询问 `DIK_ESCAPE` 时，如果 SDL3 START 正按住，直接返回 1。

用户已经实机确认 test5：START 可以正确产生 Esc 效果，练习模式能够退出。

**后续除非发现新的明确回归，不要重写这条路径。**

## 8. LT/RT 与右摇杆鼠标：已实机通过

### 8.1 规则

- 右摇杆：游戏鼠标坐标；
- LT：鼠标右键；
- RT：鼠标左键；
- LT/RT 不再同时作为游戏普通手柄按钮。

### 8.2 失败方案

test3/test4 只在较晚的鼠标公开状态或单一源状态中写按钮，实机点击没有效果。

### 8.3 成功方案

test5 起双层注入：

1. `0x40C750` 原生采集后，OR 到 `0x00504A74` 原生鼠标按钮源状态；
2. `0x40C710` getter 返回给 UI 时，再把同一份手柄鼠标按钮 OR 到最终输出。

同时根据上一帧 LT/RT 状态构造 held 与 pressed edge。

用户已实机确认 test5：LT/RT 鼠标点击正常。

## 9. 战斗移动规则

### 9.1 手柄

```text
D-Pad：
  单按/按住 -> 原版步行
  双击同方向并保持第二下 -> 原版跑步

左摇杆：
  有明确方向输入 -> 直接走原版跑步 action
```

### 9.2 键盘

```text
数字小键盘 8246：原版步行 / 双击跑
数字小键盘 7913：原版斜向
方向键：直接跑步
```

该规则覆盖原版设置中“方向键 / 数字小键盘”两套方案切换，不让设置反向改变这套固定分工。

### 9.3 重要历史修正

早期设计曾误把 D-Pad/8246 定义为“永远只能步行”。用户随后指出正确目标应是保留 PC 原版语义。因此从 test3 起，D-Pad/8246 不再锁步行，而是完整保留双击跑。

## 10. 战斗外方向输入

现代手柄的 D-Pad 与左摇杆都应进入同一套原版方向逻辑，让标题、普通菜单、设置、剧情等界面都可以用十字键导航。

插件不重新设计菜单焦点或菜单重复速率，只负责让 D-Pad 能生成和左摇杆同级的原版方向输入。

## 11. 光标自动隐藏：永久删除

用户多轮实机确认 test3/test4 的隐藏规则仍无法覆盖游戏全部光标形态，包括 VOICE 圆形光标。继续逆向成本和维护风险不值得。

从 test5 起已经删除：

- `AutoHideSeconds`；
- 光标可见状态机；
- 普通光标/VOICE 光标识别；
- Cursor.spr 槽位隐藏；
- 光标绘制 Hook。

当前插件**完全不负责光标显示/隐藏**，由原版游戏自己决定。

如果未来重新研究，必须作为独立实验线，不应污染当前稳定输入插件。

## 12. 剧情 Right 菜单：test1~test6 全部失败，test7 永久删除运行时功能

这是本项目最重要的“失败经验”之一，必须保留详细记录，防止后续重复踩坑。

### test1

把 Right 伪装成逻辑 `0x0020` / B 类菜单快捷。实机发现这只是重复了 B 原本就能做的另一种菜单操作，不是用户目标。

### test2

尝试直接维护右侧小快捷栏的 `state/focus/item`。出现战斗中 Right 仍会误响应，并且用户遇到“从快捷菜单进入剧情地图、返回后进程不死但剧情无法继续”的恶性软锁风险。此类直接写内部状态永久废弃。

### test3 / test4

尝试用 Message.ani、非战斗、安全门槛、绘制证据等限制触发范围，但正常有对话框时仍可能打不开；同时目标菜单识别也不稳定。

### test5

确认目标不是 B 菜单，而是“鼠标悬停右侧小图标栏，再点最下面 action id 8 按钮后出现的完整菜单”。插件直接执行 action 8 时，日志显示已执行，但画面必须再动一下右摇杆才真正出现，说明跳过了原版完整 hover/hit-test/click/UI 提交流程。

### test6

尝试跨帧复刻：右边缘 hover -> action 8 hit-test -> 左键 pressed。用户最终确认依然无效。

### test7 最终决定

用户明确要求：**完全删除方向键右打开快捷菜单功能。**

因此 test7：

- 删除 `0x483CA0` Hook；
- 删除 Message.ani 扫描；
- 删除剧情菜单所有全局状态；
- 删除 Right 按下沿记录；
- 删除 action 8 / 侧栏 hover / 临时鼠标自动化；
- Right 不被插件消费；
- 文档只保留历史失败记录。

未来如果有人重新研究，必须作为独立支线重新证明，不得直接把 test1~test6 代码塞回正式插件。

- `BaldrForceCN Runtime v1.0.1`
- `BaldrForceVoiceSE v0.1.1-test1`
