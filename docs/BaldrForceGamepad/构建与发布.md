## 3. 一键构建

### 3.1 全项目

在项目根用 **cmd** 运行：

```bat
build_all.bat
```

只编译单个模块（`build_all.bat` 后面跟别名，可选项 `BGMSE` / `CN` / `GAMEPAD` / `VOICESE`）：

```bat
build_all.bat GAMEPAD
```

`build_all.bat` 依次调用四个模块的 `build.bat`，先做环境自检（探测 `clang.exe`、`lld-link.exe`、
`python.exe`），确保 `release` 存在，最后打印产物目录清单。它本身不产生任何中间文件。
模块脚本会 `cd` 到自身目录，所以每次调用前后都要回到项目根，并且必须用绝对路径调用模块脚本。

### 3.2 单模块

也可以直接运行 `source\BaldrForceGamepad\build.bat`（脚本自己 `cd /d "%~dp0"`，
从任何目录调用都不会跑错相对路径）。脚本只做四件事：

1. **找工具链**：按第 2 节的顺序定位 `clang.exe` 与 `lld-link.exe`，找不到就报错退出；
   并把 clang 所在目录插到 `PATH` 最前。
2. **清理并编译**：删除旧 `_build`，重建，然后编译 x86 对象文件：

   ```text
   clang.exe -target i686-pc-windows-msvc -m32 -O2 -ffreestanding -fno-builtin ^
             -fno-stack-protector -fno-ident -Wall -Wextra ^
             -c "src\BaldrForceGamepad.c" -o "_build\BaldrForceGamepad.obj"
   ```

3. **链接 ASI**（产物直接写包根 `release`，必要时创建该目录）：

   ```text
   lld-link.exe /dll /machine:x86 /nodefaultlib /timestamp:0 /entry:DllMain ^
                /subsystem:windows,6.0 ^
                /out:"..\..\release\BaldrForceGamepad.asi" "_build\BaldrForceGamepad.obj"
   ```

   链接后删除 `release\BaldrForceGamepad.lib` / `.exp` / `.pdb`
   （lld-link 有时会顺带生成，玩家不需要）。
4. **复制随包文件**：`xcopy /y /q /i "templete\*" "..\..\release\"`；如果
   `third_party\SDL3\SDL3.dll` 存在，一并复制成 `release\SDL3.dll`，否则只打印提示。

成功时退出码 0，失败走 `:fail` 分支并清理 `_build` 后返回 1。

## 7. 构建约定

- 目标平台固定 PE32 / i386，`/machine:x86` 在链接阶段再次锁定；
- `/nodefaultlib`：不链接 MSVC CRT，成品不要求额外的 VC 运行库；
- `/entry:DllMain`：使用源码自己的最小 DLL 入口；同时导出 `InitializeASI`，
  兼容主动查找该导出的 Loader；
- `/subsystem:windows,6.0`；
- `-ffreestanding -fno-builtin -fno-stack-protector -fno-ident`：源码自备 `StrLenA`/`CopyText` 等，
  不依赖 CRT，也不让编译器把循环合成为需要链接的库函数；
- `-fno-builtin-strlen` 的说明：clang 22 会把循环合成为 `strlen` 调用，在 `/nodefaultlib` 下
  会报 `undefined symbol: _strlen`，因此 **BGMSE 与 VoiceSE 必须显式加 `-fno-builtin-strlen`**；
  本模块用的是整体 `-fno-builtin`，不受这个问题影响；
- **确定性**：`/timestamp:0` 固定 PE 时间戳，相同源码 + 相同工具链重复构建得到相同 SHA256
  （CN 模块用 `/Brepro`）；
- **临时文件**：只进模块内 `_build`，脚本在构建前与构建后各删一次；`build`、`__pycache__`、
  `*.pyc` 的清理是 BGMSE/CN/VoiceSE 这类带构建期 Python 的模块才有的，本模块没有这些目录；
- **产物落点**：只能进项目根 `release`，模块内不再建 `release`；模块脚本用
  `..\..\release` 表达这个位置，所以模块必须先 `cd` 到自身目录；
- **随包文件**：`templete` 目录存放要随 ASI 一起分发的文件，构建时 `xcopy` 到 `release`。
  本模块 INI 的唯一维护点是 `source\BaldrForceGamepad\templete\BaldrForceGamepad.ini`，
  改配置只改这一份，`release` 里的副本由构建生成；
- **文本格式**：`.md` 用 LF + UTF-8 无 BOM；`.bat` 用 CRLF + UTF-8 无 BOM，
  且 `REM`/`ECHO` 后接中文的行尾补两个半角空格，避免行尾字符被 cmd 误解析。

改源码后需要同步检查的东西（当前目录规范下只剩这些）：

- `source\BaldrForceGamepad\templete\BaldrForceGamepad.ini`（规则或参数变化时）；
- `docs\BaldrForceGamepad\完整接档说明.md`（地址、Hook、规则、测试标准变化时）；
- `docs\BaldrForceGamepad\构建与发布.md`（构建参数、产物哈希变化时）；
- `docs\BaldrForceGamepad\更新记录.md`（每次版本变化追加一条）。
