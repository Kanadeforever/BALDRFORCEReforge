# 更新记录

只记录版本与关键变更。功能原理、地址、失败方案的完整说明见《完整接档说明.md》，
构建参数与产物哈希见《构建与发布.md》。

## 2026-09-25 目录重组与构建统一（仍是 v0.1-test7 包，运行时代码未改）

- 仓库改为按模块分目录：每个模块在 `source\<模块>\` 下有 `build.bat` / `src` / `tools` /
  `data` / `templete`；本模块相应移到 `source\BaldrForceGamepad`。
- 全部编译产物统一到项目根 `release`，模块内不再有 `release`；新增项目根总编译脚本
  `build_all.bat`，后面跟 `BGMSE` / `CN` / `GAMEPAD` / `VOICESE` 可只编一个模块。
- 构建链改用本机 LLVM 工具链：clang 22.1.7 + lld-link，脚本探测顺序为 `PATH` ->
  `C:\msys64\clang64\bin` -> `C:\Program Files\LLVM\bin`，并把 clang 所在目录插到 `PATH` 最前。
  不再需要 Visual Studio / MSVC。
- 新增 `templete` 随包复制：本模块 INI 的维护点从旧的 `source\config\` 移到
  `source\BaldrForceGamepad\templete\BaldrForceGamepad.ini`，构建时复制到 `release`。
- 本模块的构建修正：脚本自己 `cd /d "%~dp0"` 并先删旧 `_build`；链接改用
  `/nodefaultlib /machine:x86 /timestamp:0 /entry:DllMain /subsystem:windows,6.0`，
  产物直接写 `..\..\release\`；构建后删除 `release` 下误生成的 `.lib`/`.exp`/`.pdb`；
  可选复制 `third_party\SDL3\SDL3.dll` 并在缺失时给出提示；控制台切 UTF-8 保证中文提示正常。
- 新增/确定的构建事实：`-fno-builtin`（本模块）与 `-fno-builtin-strlen`（BGMSE、VoiceSE 必需）
  的关系；`/timestamp:0` 带来确定性哈希。
- 文档合并为三篇：`完整接档说明.md`（覆盖原同名文件，并入构建说明、测试说明、配置说明、
  第三方依赖说明的全部内容）、新建的 `构建与发布.md`、本 `更新记录.md`。
- 本机重建验证：`release\BaldrForceGamepad.asi` 12288 字节 /
  `383f2102d549e39ac39860d694d4aba474894c529b26380dc21399e7b8b98df9`，`-Wall -Wextra` 无告警；
  用同一源码在本机重新编译到临时目录，得到逐字节相同的结果。

## v0.1-test7

删除失败功能、收敛稳定核心的版本，不新增功能。

- 按用户明确要求**完全删除**“方向右打开剧情快捷菜单/完整菜单”的全部运行时功能：
  删除 `0x483CA0` Hook、Message.ani 扫描、剧情菜单全局状态、Right 按下沿记录、
  action 8 / 侧栏 hover / 临时鼠标自动化；Right 不再被插件消费，恢复原版方向右语义。
- 因删除该 Hook，安装前核对的机器码从六处缩为五处；正式 Hook 只剩
  `0x40C700`、`0x40C710`、`0x40C750`、`0x411920`、`0x41866A`。
- `0x486C60` 一并退出运行时；静态检查确认成品 ASI 中不再出现 `0x483CA0`、
  `0x5B3140`、`0x72DC78`。
- START=Esc、LT/RT 双层注入、右摇杆鼠标、D-Pad 原版走/双击跑、左摇杆直接跑、战斗外 D-Pad 导航均不改。
- 当轮构建记录：Clang 17 + lld-link 17，成品 SHA256
  `cbff475bb7b0e97c594c8c2bc978da5334f1814296fc85735c9bb6d319d05854`。该哈希是历史环境产物，
  不是当前值；当前产物见《构建与发布.md》第 4.1 节。

## v0.1-test5

START=Esc 与 LT/RT 鼠标键实机通过的版本，同时删除光标自动隐藏。

- START：在统一输入层补 `0x1000`，并新增 `0x40C700` Hook 直接响应 `DIK_ESCAPE` 查询，
  覆盖练习模式这类绕过统一输入的代码；查询 Esc 时顺手刷新一次 SDL3 状态。
  用户实机确认练习模式可以退出。
- LT/RT：改为**双层注入**——`0x40C750` 采集后 OR 进源状态 `0x00504A74`，
  `0x40C710` getter 再把同一份按钮位 OR 进最终输出；同时按上一帧构造 held 与 pressed edge。
  用户实机确认鼠标点击正常。
- 删除光标自动隐藏的全部实现：`AutoHideSeconds`、光标可见状态机、普通/VOICE 光标识别、
  `Cursor.spr` 槽位隐藏、光标绘制 Hook。多轮实机证明无法覆盖游戏全部光标形态。
- 确认剧情 Right 的真正目标不是 B 菜单，而是“悬停右侧小图标栏 -> 点最下面 action id 8 出的完整菜单”；
  插件直接执行 action 8 时日志显示已执行但画面不动，说明跳过了原版 hover/hit-test/click/UI 提交流程。

## v0.1-test3

- 修正错误设计：D-Pad / 数字小键盘 8246 不再被锁成“永远只能步行”，恢复原版双击跑语义；
  源码中从此不提供 `FORCE_WALK`，只保留 `ORIGINAL` 与 `FORCE_RUN` 两种模式。
- 键盘固定方案成型：8246 走/双击跑、7913 斜向、方向键直接跑，不受游戏设置反向覆盖。
- LT/RT 只写公开层 `0x7CF348`；实机点击无效。
- Right 菜单继续尝试限定触发范围，实机不稳定。

## v0.1-test2

- 放弃“旧 DInput 恰好看见哪些按钮”的思路，改为按 XIDI 已验证的 1~12 物理槽位坐标自建按钮位图；
  START 继续扮演第 10 个物理按钮（练习模式无法退出的问题在此版暴露）。
- Right 菜单改为直接维护右侧小快捷栏的 `state/focus/item`：战斗中也误响应，并出现
  “从快捷菜单进入剧情地图、返回后进程不死但剧情无法继续”的软锁风险；
  此类直接写内部状态的做法永久废弃。
