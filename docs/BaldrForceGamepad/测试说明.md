# BaldrForceGamepad v0.1-test7 测试说明

v0.1-test7 是一次“删除失败功能、收敛稳定核心”的回归版。测试重点不是剧情 Right 菜单，而是确认删除该功能后，其余已经通过的输入功能没有回归。

## 1. 启动日志

正常初始化应至少看到：

```text
[BaldrForceGamepad v0.1-test7] 目标 EXE 特征验证通过。
[配置] 已读取 BaldrForceGamepad.ini。
[SDL3] 运行库已载入；手柄子系统将在游戏主线程初始化。
[成功] 原生键盘查询、鼠标 getter/采集、统一输入、步行/跑步 Hook 已安装。
```

本版日志**不应再出现**：

```text
剧情菜单
Right 请求
action 8
Message.ani
右侧快捷栏
```

因为相关运行时代码已经删除。

## 2. Right 删除功能回归——最高优先级

分别在：

- 战斗；
- 正常剧情对话；
- 剧情地图；
- 普通菜单；
- 标题；
- 场景切换前后；

反复按 D-Pad Right / 对应方向右。

预期：

- 插件不打开任何剧情快捷菜单；
- 不产生延迟弹出；
- 不移动内部鼠标去右边缘；
- 不改变剧情对象 focus/state；
- Right 只按原版方向逻辑工作。

## 3. START=Esc 回归

该功能在 test5 已实机通过，但 test7 必须确认删除剧情 Hook 后没有回归。

重点：

1. 进入练习模式；
2. 按手柄 START；
3. 应和键盘 Esc 一样退出。

同时在可以用 Esc 返回的普通菜单中再确认一次。

## 4. LT/RT 鼠标键回归

已知成功规则：

```text
RT = 鼠标左键
LT = 鼠标右键
```

测试几个真正支持鼠标点击的界面，确认：

- 按下能触发；
- 松开不会粘住；
- 连续点击正常；
- LT/RT 不额外触发游戏普通手柄动作。

## 5. 右摇杆鼠标

- 上下左右连续移动；
- 小幅移动是否平滑；
- 灵敏度 INI 是否生效；
- 不需要测试自动隐藏，因为该功能已删除。

## 6. 战斗 D-Pad 原版语义

逐方向测试：

1. 单次按住 D-Pad -> 步行；
2. 松开；
3. 快速双击同方向并保持第二次 -> 跑步。

四方向都要测。

## 7. 左摇杆直接跑

战斗中从静止直接推动左摇杆：

预期无需双击，直接进入原版跑步。

同时测试：

- 轻微方向变化；
- 连续转向；
- 攻击前后移动；
- 多次停下再起步。

## 8. 键盘固定方案

无论游戏设置里选择原来的哪套方向方案，都测试：

- 数字小键盘 8246：步行 / 双击跑；
- 7913：斜向；
- 方向键：直接跑。

## 9. 战斗外 D-Pad 菜单

在标题、设置、普通列表、剧情 UI 等场景确认：

- D-Pad 能和左摇杆一样上下左右导航；
- 不出现一次输入跳两格；
- 不出现 Right 被插件吃掉。

## 10. 三插件组合回归

当前常用组合：

- BaldrForceCN Runtime v1.0.1；
- BaldrForceVoiceSE v0.1.1-test1；
- BaldrForceGamepad v0.1-test7。

至少走：

1. 读档进入剧情；
2. 剧情推进；
3. 剧情地图进入/返回；
4. 战斗；
5. 练习模式 START 退出；
6. 鼠标相关 UI；
7. 再回剧情。

重点观察是否还有 test2 那类“进程未卡死但剧情无法继续”的软锁。

## 11. 通过标准

如果以下全部通过，可把 test7 视作稳定基线并准备 v0.1 RC：

- Right 剧情菜单功能完全不存在；
- START=Esc 不回归；
- LT/RT 不回归；
- 右摇杆鼠标正常；
- D-Pad 原版走/双击跑正常；
- 左摇杆直接跑正常；
- 战斗外 D-Pad 菜单正常；
- CN + VoiceSE 共存无软锁。
