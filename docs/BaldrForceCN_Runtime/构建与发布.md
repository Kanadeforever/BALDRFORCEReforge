## 2. 依赖与工具链

| 依赖 | 说明 |
|---|---|
| clang | 22.1.7，本机位于 `C:\msys64\clang64\bin` |
| lld-link | 与 clang 同目录 |
| Python 3 | 只被 `tools` 下的校验/审计脚本使用，不参与编译 |

探测顺序（`build_all.bat` 与模块 `build.bat` 一致）：先查 `PATH`，再查 `C:\msys64\clang64\bin`，最后查 `C:\Program Files\LLVM\bin`。找到 clang 后把**它所在目录插到 `PATH` 最前**，因为 clang.exe 依赖同目录的 DLL。

本模块的编译参数：

```text
--target=i686-pc-windows-msvc -O2 -ffreestanding -fno-builtin
-fno-stack-protector -fno-exceptions -fno-asynchronous-unwind-tables
-Wall -Wextra -Werror
```

链接参数：

```text
/dll /machine:x86 /nodefaultlib /entry:DllMainCRTStartup /subsystem:windows
/safeseh:no /opt:ref /opt:icf /export:InitializeASI /Brepro
```

其它约定：

- **CN 已改为纯 clang + lld-link 路线，不再需要 Visual Studio / MSVC**。
- MSYS2 的 clang64 不提供 `clang-cl.exe`，所以统一使用 `clang.exe`（BGMSE 与 VoiceSE 另用它的 cl 驱动模式 `--driver-mode=cl`）。
- 四个模块统一 `/nodefaultlib`、PE32/i386、无 CRT。
- BGMSE 与 VoiceSE 必须额外带 `-fno-builtin-strlen`：clang 22 会把循环合成为 `strlen` 调用，而 `/nodefaultlib` 下没有 `strlen` 可链接，会报 `undefined symbol: _strlen`。**CN 的构建参数里没有这个开关**，2026-09-25 本机构建通过（是否在个别源码改写后会触发该合成，未逐条确认）。
- 构建确定性：BGMSE/VoiceSE/Gamepad 用 `/timestamp:0`，**CN 用 `/Brepro`**。

## 3. 一键构建

项目根，用 **cmd**：

```bat
build_all.bat             :: 依次编译四个模块
build_all.bat CN          :: 只编译本模块（可选：BGMSE / CN / GAMEPAD / VOICESE）
```

`build_all.bat` 的行为：先做环境自检（探测 clang.exe、lld-link.exe、python.exe 并打印来源），确保项目根 `release\` 存在，然后依次调用四个模块的 `build.bat`。模块脚本会 `cd` 到自身目录，因此总脚本每次调用前后都切回项目根，并用**绝对路径**调用模块脚本；模块产物写向上两级的 `release`，所以 **release 永远位于项目根**，不在模块内部另建。任何一个模块返回非 0 就算失败，最后打印成功/失败计数与产物目录。

也可以只构建本模块：

```bat
source\BaldrForceCN_Runtime\build.bat
```

`build.bat` 的步骤：

| 步骤 | 内容 |
|---|---|
| 0 | 解析工具链（clang / lld-link），把 clang 目录插到 PATH 最前 |
| 1 | 清空并重建模块内临时目录 `build\`，确保上两级 `release\` 存在 |
| 2 | 编译 `src\BaldrForceCN.c` → `build\BaldrForceCN.obj` |
| 3 | `pushd src` 后编译 `embedded_assets.S` → `build\embedded_assets.obj`，再 `popd` |
| 4 | lld-link 链接成 `..\..\release\BaldrForceCN.asi`，并删除 release 里误生成的 `.lib / .exp / .pdb` |
| 5 | 复制 `src\assets\Chapter.pac`、`src\assets\Update.pac` 到 `..\..\release\` |
| 6 | `xcopy templete\*` 到 `..\..\release\`（随包文件） |
| — | 收尾清理 `build\`、`__pycache__\`、`*.pyc`；失败时走同一套清理 |

第 3 步为什么先 `pushd src`：`embedded_assets.S` 里的 `.incbin` 用的是**裸相对路径** `assets/BMP/Hell/Font.grp` 这种写法。先切到 `src` 再汇编，无论汇编器按「工作目录」还是按「源文件所在目录」解析，结果都指向 `src\assets\`。

## 5. 工具说明

`source\BaldrForceCN_Runtime\tools\` 下共 5 个 Python 脚本。

> **路径约定（2026-09-25 已修复）**：脚本不再用 `ROOT` 去推导项目根。现在统一为 `ROOT` = 本模块目录、`PROJECT` = 项目根、`SRC` = `<模块>/src`、`RELEASE` = `<项目根>/release`、`DOCS` = `<项目根>/docs/BaldrForceCN_Runtime`。五个工具现在全部可用，实测结果见 5.6。

| 脚本 | 用途 | 输入 | 输出 | 当前状态 |
|---|---|---|---|---|
| `verify_release_package.py` | 发行包自检，不需要游戏 EXE | `release\`、`src\`、`data\`、`docs\` | stdout 逐项 PASS/FAIL 与最终 `RESULT` | **可用**（实测 PASS，69 PASS / 0 FAIL / 1 SKIP） |
| `verify_static.py` | 对 clean EXE 做签名/补丁/静态表/资源/PE 校验 | `python tools\verify_static.py <clean BaldrForce.exe>` | stdout 逐项 PASS/FAIL、ASI SHA256 | **可用**（需固定 clean EXE；缺 EXE 时打印用法并退出 2） |
| `audit_bfet_length_semantics.py` | 统计 34,184 条 BFET 的中日长度分布 | `<项目根>\release\Update.pac` | stdout 统计 | **可用**（实测 exit=0） |
| `audit_bfet_backlog_risks.py` | 统计「二次消费者错误复用源 count」的截断风险 | `<项目根>\release\Update.pac` | `data\BFET_Backlog风险审计.csv`、`data\脚本历史记录风险审计摘要.txt` | **可用**（实测 exit=0，重跑输出与仓库一致） |
| `audit_vfs_resources.py` | 生成 313 文件 VFS 发行资源清单 | `<recovered_vfs> [模块目录]`（模块目录可省略） | `<模块目录>\data\旧汉化VFS资源审计.csv`、`旧汉化资源审计摘要.txt` | **可用**（需自备 recovered_vfs） |

### 5.1 verify_release_package.py

不需要游戏 EXE。检查 release 四文件、两个 PAC 的大小与固定 SHA256、INI 只公开 FontFace/EnableLog、ASI 的 PE32/i386/DLL/Import Directory=0/InitializeASI、9 个 source asset 的固定哈希与「在 ASI 中各出现一次」、313 文件审计的 `11 COVERED + 302 PASS + 0 REVIEW`、Unicode glyph fallback、脚本双长度语义、中文日志前缀、增强 VEH、Backlog 审计、文档版本同步。

### 5.2 verify_static.py

`python source\BaldrForceCN_Runtime\tools\verify_static.py <clean BaldrForce.exe>`。固定 clean SHA256：

```text
5b65ecb1512b0cbf72cacdb5e981aa04f9c569698c6cab2f8877abf2d2cd42c5
```

它内置的期望表就是本文档多处引用的真值来源：

- `SIGS`：renderer.parse/width/late、script.op0B、glyph.drawA/drawB、resource.open、两个 lookup 的 clean 长签名与 VA；
- `OLD_LOCALIZATION_PATCH_BYTES`：五处低层补丁点的 clean 原字节；
- `EXPECTED_EMBEDDED_ASSETS`：9 个差异 loose 的大小与 SHA256；
- `EXPECTED_DAT`：10 个 DAT 的大小与 SHA256；
- 静态文本表（UI / legacy / late / encoding-normalization）的逐条 RVA、原文 FNV 哈希与替换结果。

有固定 clean EXE 的机器应当运行它；没有该 EXE 时**不要**伪造 PASS。

### 5.3 audit_bfet_length_semantics.py

只读 `release\Update.pac`，不修改任何游戏文件。输出固定统计：34,184 条中 3,909 等长、29,633 中文更短、642 中文更长（长度不同合计 30,275）。它现在的用途是**解释为什么运行时 value object 不能沿用源 count**，而不是证明「必须保留原 byte_count」。

### 5.4 audit_bfet_backlog_risks.py

统计「某个二次消费者绕过 value object、直接拿源 count 截中文」的风险：642 条中文更长中 627 条会切进 GBK 双字节；另记录 1 条中文自身引号不平衡、6 条中日引号数量变化。v1.0.4 已修正正式 value object 的 byte_count，但该工具继续保留，作为以后发现其它错误消费者时的风险地图。

### 5.5 audit_vfs_resources.py

用法 `python audit_vfs_resources.py <recovered_vfs> [模块目录]`。它不重新做 clean 对比（输入里只有旧 VFS），而是：枚举 313 文件；2 个 PAC 标 COVERED；9 个差异 loose 标 COVERED；其余 302 标 PASS；任何不在固定路径分类中的文件进 REVIEW 让发布检查失败。

第二个参数省略时默认取本脚本所在模块目录，结果写入该模块的 `data`，不会在项目根误建 `data` 目录。它需要调用方自备旧汉化 313 文件的 recovered_vfs 目录；脚本注释里提到的原版对比 PNG 与差异资源 zip 属历史证据，当前仓库中**不存在**，但不影响本工具运行。

## 7. 构建约定

- **自清理**：模块脚本在构建前后清理 `build\`、`__pycache__\`、`*.pyc`，并从 release 删除误生成的 `.lib/.exp/.pdb`。
- **确定性**：CN 链接使用 `/Brepro`，相同源码 + 相同工具链重复构建得到相同 SHA256。注意工具链版本变化会改变产物哈希（旧文档记录的 ASI 哈希就是这样过期的）。
- **templete 随包复制**：`templete\` 存放随 ASI 一起分发的文件（本模块是 `BaldrForceCN.ini`），构建时 `xcopy` 到 release。改动 `templete\BaldrForceCN.ini` 就等于改动发行包，不需要重新编译；INI 不参与编译。
- **PAC 复制而非内嵌**：两个 PAC 由构建脚本从 `src\assets\` 复制到 release，`embedded_assets.S` 不引用它们，所以 PAC 变化不改变 ASI 字节。
- **`.incbin` 相对路径**：汇编前先 `pushd src`，写法保持裸相对路径，避免依赖汇编器的路径解析习惯。
- **脚本编码**：`.bat` 用 CRLF + UTF-8 无 BOM，第一行后 `chcp 65001 >nul`；`.md` 用 LF + UTF-8 无 BOM。
- **一键总控**：新增或改名模块时要同时改 `build_all.bat` 的 `:run` 调用行与别名映射。

## 8. 已知构建问题

1. **旧文档引用过的构建脚本已不存在**
   `build_clang.bat`、`build_msvc.bat`、`build_clang_linux.sh` 在当前仓库中都不存在（`build_clang_linux.sh` 是作者主动删除）。当前唯一入口是 `build_all.bat` 与模块 `build.bat`。任何提到「容器/Linux 交叉编译复核」的旧描述都已失效。

2. **`.gitignore` 的影响**
   `.gitignore` 排除了 `release/`、以及 VoiceSE 的 `data` 下 `BFE/` 与 `BFSE/`。后果：仓库里没有编译产物（`release` 需自行构建）；直接克隆后 **VoiceSE 无法构建**（缺少 BFE 脚本输入）。本模块不受影响：`src\assets\Update.pac` 与 `Chapter.pac` 都已被 git 跟踪，克隆后可以正常构建 CN。

3. **Gamepad 需要手工放置第三方 DLL**
   Gamepad 需要手工把 third_party 下 SDL3 的 **x86 `SDL3.dll`** 放进 `source\BaldrForceGamepad\third_party\SDL3\`，否则 release 里不会出现 `SDL3.dll`（`.gitignore` 排除 `*.dll`）。与本模块无关，但同一条总构建链上。

4. **旧构建数字必须替换**
   任何仍写着 `ASI 2,040,320 / 29fc70be...` 的文本都是重组前的旧值，当前真值见 4.1。
