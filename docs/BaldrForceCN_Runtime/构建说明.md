# 构建说明

> 当前版本：`v1.0.4-crashfix1`。工程为 Win32/x86、无 CRT、无第三方运行库依赖。

## 1. 目录

```text
source\BaldrForceCN.c
source\embedded_assets.S
source\assets\...            9 个旧汉化差异 loose 资源
build_clang.bat               Windows LLVM 构建
build_msvc.bat                历史/辅助入口，不作为正式资源内嵌发行主线
build.bat                     一键入口
release\                     最终运行文件
```

`.incbin` 把 9 个差异资源原字节链接进 ASI，因此正式构建固定使用 Clang/LLVM 路线。

## 2. Windows 一键构建

直接运行：

```bat
build.bat
```

需要 PATH 中有 `clang.exe` 和 `lld-link.exe`。脚本使用 `--target=i686-pc-windows-msvc`、`-ffreestanding`、`-fno-builtin`、`-fno-stack-protector`、`-Wall -Wextra -Werror`，链接使用 `/nodefaultlib /machine:x86 /safeseh:no`。

## 3. 容器/Linux 复核

```bash
bash source/build_clang_linux.sh
```

只负责交叉编译，不运行游戏。

## 4. 发行验证

无 clean EXE：

```text
python tools\verify_release_package.py
```

有固定 clean 2003 EXE（SHA256 `5b65ecb1512b0cbf72cacdb5e981aa04f9c569698c6cab2f8877abf2d2cd42c5`）：

```text
python tools\verify_static.py <BaldrForce.exe>
```

最终 `release` 必须恰好四个文件：`BaldrForceCN.asi / BaldrForceCN.ini / Update.pac / Chapter.pac`。

## 5. 本版新增构建点

`BaldrForceCN.ini` 不参与编译，只随 release 发布。源码通过运行时解析 `GetPrivateProfileStringW` 读取它，因此 ASI 仍不产生静态 Import Directory。

字形修复新增 `GetGlyphOutlineW` fallback，但该 API 与之前一样通过运行时解析 gdi32 导出使用，不增加链接库。脚本双长度修复仅改 `Hook_ScriptCopyBytes()` 的运行时 `dest-4` 写入，不改变 Hook 地址 `0x004ACC20`。
