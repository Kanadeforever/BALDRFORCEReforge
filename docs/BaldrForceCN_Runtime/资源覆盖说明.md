## 1. 当前资源模型（与 v1.0.0 最终差分结论相同）


## 4. 9 个 loose 文件如何内嵌

`source/embedded_assets.S` 对每个文件使用 `.incbin`。运行时只对白名单路径接管 `CreateFileA`：

```text
游戏 CreateFileA(白名单路径)
    -> 在 ASI 同目录创建隐藏 delete-on-close backing file
    -> 写入内嵌的旧汉化原字节
    -> 文件指针归零
    -> 返回真实 Windows HANDLE
    -> 游戏继续原生 ReadFile/GetFileSize/SetFilePointer/CloseHandle
```

其它路径完全不拦截。

## 5. 10 个 DAT overlay

当前从 `Update.pac` 直接提供：`CGInfo.DAT`、`ChapterFlowInfo.DAT`、`DatabaseInfo.DAT`、`EquipmentInfo.DAT`、`FlgInfo.DAT`、`FlowInfo.DAT`、`ItemInfo.DAT`、`ReplayInfo.DAT`、`SceneInfo.DAT`、`VisualInfo.DAT`。它们进入原引擎正常 DAT 解析器，不需要 loose 文件。

## 6. after.bin

`after.bin` 是旧汉化新增、原版 PAC 不存在的脚本；当前 `Update.pac` 完整保留它，汉化 `Title.bin` 有真实 `after.bin` 引用。它无 BFET 尾部，因此 Runtime 从其直接 GBK 区建立 9 条 direct-entry。v1.0.4-crashfix1 第一次真正执行 direct-entry 时仍记录中文日志：

```text
[命中] after.bin 直接 GBK 脚本文本已执行（运行时已确认）
```

没有进入对应附加页面时日志不出现属于正常。
