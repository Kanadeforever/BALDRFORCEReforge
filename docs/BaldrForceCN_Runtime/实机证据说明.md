# 实机证据说明

## 已通过的功能证据

test11 实机确认 Information/阅览信息与 TORU 练习招式完全恢复中文；test12 实机确认 HELLMODE 中文图片恢复。用户随后对 311 个 loose 文件做全量二进制比较，确认只有 9 个与 clean 原版不同，302 个完全相同；v1.0.x 的资源白名单据此冻结。

## v1.0.3 第一次崩溃：八木泽名片

证据：`v1.0.3_第一次_八木泽名片崩溃.log`。关键现场：主程序 `EIP=0x0048A974`、读取 `0xFFFFFFFF`、最后 BFET 为 `jyosyo05.bin #49 71->71`、`glyph_failures=1`。这份日志推翻了“下一句长度差就是该崩溃直接原因”的猜测，并把修复点收敛到普通 GBK glyph fallback。

## v1.0.3 第二次崩溃：缺结束符后打开 Backlog

证据：`v1.0.3_第二次_Backlog崩溃.log` 与 `v1.0.2_Backlog前扩张文本末尾方块_打开Backlog崩溃.png`。`jyosyo05.bin #64` 为 JA 20 -> ZH 26，原脚本 count=21；中文数据本身 `「」` 成对。v1.0.3 运行时对象仍保留 count=21，因此末尾视觉截断和 Backlog 二次消费崩溃具有直接字节级解释。

## v1.0.4 等待验收

本版分别加入 Unicode glyph fallback/安全空白字形和“源 count / value object byte_count 分离”修复。尚未把这两项写成“实机通过”；必须等用户重新测试八木泽名片和 #64 Backlog 后再升级为稳定结论。

## after.bin

静态证据确认 after.bin 是旧汉化新增、原版不存在，汉化 Title.bin 会引用它；当前 Update.pac 完整保留。direct-entry 首次实际执行时日志仍输出 `[命中] after.bin 直接 GBK 脚本文本已执行（运行时已确认）`。
