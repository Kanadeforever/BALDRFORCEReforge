# BaldrForceCN Runtime 更新记录

> 只记录版本、日期与关键变更要点。技术结论、地址、证据链与已证伪方案见 `完整接档说明.md`；构建与发布细节见 `构建与发布.md`。

## 仓库重组（构建与文档）— 2026-09-25

本轮**不产生新的 ASI 版本号**，功能仍是 `v1.0.4-crashfix1`；改的是仓库布局、构建脚本与文档组织。

- 目录重组为 `source\<模块>\` 下每模块一个目录，含 `build.bat / src / tools / data / templete`；文档移入 `docs\<模块>\` 并按模块分子目录。
- 所有编译产物统一到**项目根 `release\`**，模块内不再有 release；模块脚本 `cd` 到自身目录后写向上两级。
- 新增项目根总编译脚本 `build_all.bat`，依次调用四个模块的 `build.bat`；后跟 `BGMSE / CN / GAMEPAD / VOICESE` 可只编一个。
- 构建脚本改用本机 LLVM 工具链：clang 22.1.7 + lld-link（`C:\msys64\clang64\bin`），探测顺序 PATH → `C:\msys64\clang64\bin` → `C:\Program Files\LLVM\bin`，并把 clang 目录插到 PATH 最前。
- CN 相应构建修正：保持纯 clang + lld-link 路线（不需要 Visual Studio / MSVC）；链接使用 `/Brepro` 保证确定性；`embedded_assets.S` 汇编前先 `pushd src`，使裸相对 `.incbin assets/...` 与汇编器解析习惯无关；构建后从 release 删掉误生成的 `.lib/.exp/.pdb`。
- 新增 **templete 随包复制**：`templete\BaldrForceCN.ini` 在构建时复制到 release；两个 PAC 由 `src\assets\` 复制到 release（不内嵌进 ASI）。
- 工具链换代后产物哈希全部更新：`BaldrForceCN.asi` = 2,037,248 bytes / `97414b5f...`。此前的 `2,040,320 / 29fc70be...` 作废。
- 旧的 `build_clang.bat`、`build_msvc.bat`、`build_clang_linux.sh` 已不存在；tools 下四个校验脚本已改用重组后的路径（`ROOT`/`PROJECT`/`SRC`/`RELEASE`/`DOCS`）并实测可用（详见 `构建与发布.md` 第 5 节）。

## v1.0.4-crashfix1 — 2026-09-21

- 依据第一次实机崩溃日志首次取得真实异常：`EIP=0x0048A974`、读取 `0xFFFFFFFF`、崩溃前 `glyph_failures=1`；八木泽名片崩溃由此从「脚本长度猜测」转为 **GBK 字形失败后错误回退 CP932**。
- 普通 GBK renderer 继续优先走已实机通过的 ANSI/GB2312 路径；`GetGlyphOutlineA` 失败时新增 `CP936 → Unicode → GetGlyphOutlineW` 回退。
- 已判定为 GBK 的字符即使两条 GDI 路径都失败，也返回合法全 0 字形，不再返回 NULL 让汇编 stub 回 CP932。低层 1bpp mask 使用同一规则。
- 依据第二次实机日志确认 `jyosyo05.bin #64` 为 JA 20 -> ZH 26、源 `count=21`，v1.0.3 运行时对象仍为 21，与「末尾截半个 GBK + Backlog 再消费崩溃」的现场吻合。
- 正式建立**双长度语义**：脚本源游标按原日文 count 前进，运行时 `dest-4 byte_count` 用中文实际长度+NUL；BFET 与 after.bin direct-entry 都遵循。该句新日志会显示源 count=21、运行时 count=27。
- `BaldrForceCN.ini` 恢复，但只暴露 `FontFace` 与 `EnableLog`；其余编码、charset、Hook、BFET、资源参数仍固定在源码里。
- 资源白名单、两个 PAC、10 DAT overlay、9 个差异 loose、五处低层补丁与两个 1bpp Hook 地址全部未变。
