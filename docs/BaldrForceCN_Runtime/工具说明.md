# 工具说明

本包目标是“任意单包可以独立接档”。研究工具、审计 CSV、两份 v1.0.3 崩溃日志和最终差异资源都随包保存。

## verify_release_package.py

不需要游戏 EXE。检查 release 四文件、两个 PAC 固定哈希、INI 只有 FontFace/EnableLog、ASI PE32/i386/DLL/无 Import Directory/InitializeASI、9 个 source asset 固定哈希且在 ASI 中各出现一次、313 文件审计 `11 COVERED + 302 PASS + 0 REVIEW`、Unicode glyph fallback、脚本双长度语义、中文日志与增强 VEH。

## verify_static.py

`python tools\verify_static.py <clean BaldrForce.exe>`。固定 clean SHA256：`5b65ecb1512b0cbf72cacdb5e981aa04f9c569698c6cab2f8877abf2d2cd42c5`。用于验证 renderer/script/DAT opener/低层 DBCS routing-state/静态补丁/RVA 与签名。

## audit_vfs_resources.py

应用用户对 311 loose 文件的全量二进制对比结论：2 PAC + 9 差异 loose 为 COVERED，其余 302 loose 为 PASS；未知路径进入 REVIEW。

## audit_bfet_length_semantics.py

统计 34,184 条 BFET 的中日长度：3909 等长、29633 中文更短、642 中文更长。它现在用来解释为什么运行时 value object 不能沿用源 count，而不是证明“必须保留原 byte_count”。

## audit_bfet_backlog_risks.py

统计如果某个二次消费者错误拿源 count 截中文时的风险：642 条中文更长，其中 627 条会截进 GBK 双字节；另记录引号结构差异。v1.0.4 已修正式 value object 的 byte_count，但这个工具继续用于寻找其它潜在错误消费者。

## 研究工具

- `旧汉化VFS完整恢复包_v9.zip`：313 文件完整 oracle；
- `旧汉化差异资源_9文件.zip`：用户最终筛出的 9 个不同 loose 文件；
- `旧汉化主模块内存映像.zip`：旧汉化运行时代码/数据证据；
- `旧汉化运行时探针_v0.3.zip`、`隐藏模块宽扫工具_v0.4.zip`：历史逆向探针。
