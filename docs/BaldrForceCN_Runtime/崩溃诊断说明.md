# 崩溃诊断说明

> 适用版本：`BaldrForceCN Runtime v1.0.4-crashfix1`  
> 原则：修复已确认根因，同时继续保留只记录、不吞异常的增强 VEH。

## 1. 两份实机日志已经得到什么

### 第一次：八木泽递名片

`evidence\v1.0.3_第一次_八木泽名片崩溃.log`：

```text
ExceptionCode = 0xC0000005
EIP            = 0x0048A974
访问类型       = 读取
目标地址       = 0xFFFFFFFF
最近脚本       = jyosyo05.bin #49，71->71
renderer_hits  = 1290
glyph_builds   = 390
glyph_failures = 1
```

`0x0048A974` 的故障指令在原 renderer 内使用字形指针；结合 `EDI=0xFFFFFFFF` 和唯一一次 glyph failure，可把问题收敛为：已经按 GBK 分类的字符在 GDI ANSI 取字失败后又回到原 CP932 字形路径。v1.0.4 的修复是 Unicode fallback + 安全空白字形，禁止确认过的 GBK 因缺字回退 CP932。

### 第二次：#64 后打开 Backlog

`evidence\v1.0.3_第二次_Backlog崩溃.log` 先两次命中：

```text
jyosyo05.bin #64
JA 20 -> ZH 26
原 count=21
```

随后 Access Violation 落在其它系统映像中。更重要的是，事件现场证明主显示使用的译文长度和 value object 仍保存的旧 count 不一致。v1.0.4 因此恢复“运行时对象使用真实中文长度”，但脚本源游标仍按原 count 前进。

## 2. VEH 仍会记录什么

仅记录严重 CPU/内存异常：Access Violation、In-page Error、Illegal Instruction、整数除零/溢出、Stack Overflow。最后始终 `EXCEPTION_CONTINUE_SEARCH`，不改 EIP、不吞异常。

一次崩溃尽量保存：ExceptionAddress/EIP 与模块 RVA、异常参数、EAX~EDI/EBP/ESP/EFlags/段寄存器、EIP 附近机器码、故障目标与寄存器指向内存、32 个栈 DWORD、疑似代码返回地址、最多 16 层 EBP frame、最近 128 次脚本复制事件、最近 12 个仍可读 value object、最近 64 次 DBCS/字形事件，以及 renderer/glyph/mask/DAT/资源计数。

## 3. 新增字形 fallback 诊断

如果默认 ANSI `GetGlyphOutlineA` 失败，但 Unicode 路径成功，会记录：

```text
[诊断] ANSI 中文字形失败后已由 Unicode fallback 恢复，GBK字符码=...，字号=...
```

如果 ANSI 和 Unicode 都失败，会记录警告并返回安全空白字形，不再退回 CP932：

```text
[警告] GBK 字形的 ANSI/Unicode 两条 GDI 路径均失败；将返回安全空白字形而不回退 CP932...
```

崩溃计数还会输出 `ansi_outline_failures / unicode_fallbacks / hard_outline_failures`。

## 4. 日志开关

`BaldrForceCN.ini` 的 `EnableLog=0` 会让本次运行不创建/覆盖日志，因此测试崩溃时必须保持 `EnableLog=1`。关闭日志不会卸载 VEH 或改变游戏逻辑，只是所有 `log_*` 输出因为没有日志句柄而成为 no-op。
